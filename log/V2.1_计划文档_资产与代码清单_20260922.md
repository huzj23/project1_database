## 0. 四条铁律（不可回退）

> 这四条是项目已经做出的**架构级决定**。任何后续改动若与之冲突，必须先改本文档并说明理由，
> 不允许在实现里"悄悄绕回去"。

### 铁律一：仿真必须走真求解器，**禁止预定义轨迹**

```text
采样初始条件 → PyBullet 积分 → 校验 → 相机 → 渲染 → 保存
```

- **只给初始条件**（位置、朝向、初速度、质量、摩擦、恢复系数、重力/外力）
- **后续每一帧状态由 PyBullet 积分得出**，我们**不得**写死逐帧位置
- **禁止**的三种回退写法（学长 `PIPELINE.md` §4 明文列出）：
  1. 规定期望的逐帧轨迹
  2. 反复重置速度来伪造匀速运动
  3. 仿真失败后手工修补弹跳

**为什么**：阶段一我们三条运动全部是解析式预定轨迹，直接导致学长评审的
"不够物理"。这是**已被否决的路线**。

### 铁律二：只用**真实物体模型**，禁止纯色原型体

- **禁止**使用 Blender 原生纯色几何体作为被仿真物体
  （阶段一的 `ball` / `brick_box` / `jenga` 纯色体**全部作废**）
- **例外**：`kb.Sphere` 等**原生体碰撞**是允许的（学长也用），
  但**视觉必须是真实模型**——即使用原生球碰撞，渲染的也必须是真实贴图的球
- 场景同理：优先真三维场景，HDRI 贴图背景仅作退路

### 铁律三：渲染器不跑第二个求解器

- PyBullet 是**唯一**的物理真相来源
- Blender 只把校验通过的轨迹**当关键帧回放**并渲染
- **禁止**在 Blender 里再挂 Soft Body / Rigid Body 去做形变或运动
  ——那会让 `trajectory.json` 标注与画面对不上

> 软体形变因此走 **PyBullet 自己的 `loadSoftBody`**（已实测可用），不走 Blender。

### 铁律四：光照**只从场景作者配置来**，禁止私自加灯

**实测依据**（`tools/light_inventory.sh`）：

```
frl_apartment_stage.glb      lights = 0     <- 场景 GLB 里一盏灯都没有
frl_apartment_sofa.glb       lights = 0
frl_apartment_lamp_01.glb    lights = 0
lighting_config.json         light types = {'point': 7}   <- 只有点光源，无平行光
```

- 场景的灯**只存在**于 `configs/lighting/<name>.lighting_config.json`
- 那 7 盏**全部是 `point` 类型**，**没有 Sun / 平行光**
- 因此**场景自身不可能造成光源冲突**

**规定**：

| 允许 | 禁止 |
|---|---|
| 读取并启用该场景的 `lighting_config.json` | 各脚本自行添加 Sun / DirectionalLight |
| 场景作者光照**不足**时，按学长 `asset.yaml` 的规则补（先 Sun + 一个 Area，仍不足才多 Area），**并记录在场景资产里** | 在渲染脚本里临时"补个光让画面能看" |

> **背景**：装饰对照实验（`tools/decor_probe.sh`）里我曾同时加了「7 盏作者点光源 + 0.8 强度太阳光」，
> 那是为了出对比图的临时做法，**不是最终方案**。定此铁律正是为了避免"各脚本各加各的光"。

## 1. 场景清单

### 1.1 现状

> **重要修正**：初版本文档判断"ReplicaCAD 空旷不可用"——**这个判断是错的**。
> 当时只加载了 **stage（建筑外壳）**，没加载 **scene_instance（家具布局）**。
> 实测：同一个下载里附带 **95 个日常物体** + **91 个预置场景布局** + **76 个凸分解碰撞体** + **7 个作者光照配置**。
> 加载 `apt_0.scene_instance.json` 后 **113 个道具全部成功放置**，室内视角是**家具齐全的真实公寓**
> （木桌、台灯、自行车、沙发、置物架、盆栽、地毯、挂画、电视）。

### 1.2 结论与待办

**采用的场景（已定）**：

| 优先级 | 场景 | 用途 |
|---|---|---|
| **主力** | **ReplicaCAD `frl_apartment_stage` + `apt_*` 布局** | 家具齐全、无屋顶、日光可用。地板作支撑面 |
| 备用 | `Stage_v3_sc0..sc3` + 各自 `lighting_config` | 换换背景用；**必须启用作者光照** |
| — | 简易 PBR 平面 | **仅用于物理调试**（P1 早期验证求解器），不作为交付 |

**实测的比例参照**（毛绒象 0.268 m 放在地毯上）：

| 机位 | 相机距离 | 物体占画面宽 |
|---|---|---|
| 近景 | 1.50 m | **25%** |
| 中景 | 2.64 m | **14%** |

画面里有**桌腿、搁板上的锅、地毯花纹**作比例参照，物体**贴在地毯上**。

**待办**：
1. 为 `frl_apartment_stage` 标定**支撑区域**（水平合法范围 + 障碍物，如楼梯柱、桌腿）
2. 为 `sc0..sc3` 接入各自的 `lighting_config.json`
3. 把 `objects/convex/*_cv_decomp.glb` 接为**静态碰撞体**

### 2.3 球类怎么办

**GSO 全库没有标准球体**（近球形的都是花盆）。

**决定**：按你的指示——**不为球将就**。需要球形时的处理：

| 方案 | 说明 |
|---|---|
| **原生球碰撞 + 真实球贴图** | 碰撞用 `kb.Sphere`（几何完美、滚动/弹跳正确），**视觉用真实球模型**。符合铁律二（视觉必须真实） |
| 球模型来源 | ①Poly Haven 有 CC0 的球类模型 ②学长仓库的 4 个球（但他只提供碰撞配置，视觉要自备） |

### 3.3 必须保留的两个硬故障修复

这两条是踩坑换来的，**不得丢失**：

| 修复 | 位置 | 问题 |
|---|---|---|
| **深度通道 SIGSEGV 修复** | `phyco_common._owned()` + `prepare_*` 顺序 | OpenEXR 读出的 numpy 数组基于临时缓冲区，后续大分配会使其失效 → 段错误。修法：`tobytes()` 往返 + 深度优先处理 |
| **ReplicaCAD 坐标修复** | `phyco_backdrops.add_stage_direct()` | Kubric 的 glTF 路径强改旋转，把房间丢到 1300 m 外。修法：绕过 Kubric，直接 `bpy.ops.import_scene.gltf` |

## 5. 软体（毛绒落地压扁）—— P1 专项

**结论（已实测）**：**PyBullet 自己的 `loadSoftBody` 可用**，实测下落 + 落地形变 19% + 回弹，
exit code 0。**不需要 Blender 软体**（那样会破坏铁律三）。

实测数据：

```
Z 轨迹    0.800 → 0.653 → 0.235 → 0.216 → 0.230 → 0.229
竖向尺寸  0.499 → 最小 0.405 → 0.477
落地压缩 19.0%     FELL=True  DEFORMED=True
```

**待解决**：软体需要**四面体体网格**，而 GSO 只有表面网格。
需验证 PyBullet 能否从 GSO 的 OBJ 自动生成可用的体网格，否则要做体素化预处理。
