## 1. 目标与范围

### 1.1 总目标

产出**带逐帧物理标注的视频资产**，用于物理世界模型 / 可控运动生成模型的训练与评测。

### 1.2 本期范围（第一期，已确认）

在**无交互环境**（场景中只有一个运动物体，除静态地板外无其他动力学物体、无碰撞参与）下，生成单个物体的三类运动：

| 编号 | 运动类型 | 物理含义 | 状态 |
|---|---|---|---|
| A | **固定圆周运动** | 物体沿固定圆形轨迹匀速运动，含自转 | ✅ 已实现并验证 |
| B | **阻尼运动** | 速度按指数规律衰减的黏性阻尼运动 | ✅ 已实现并验证 |
| C | **旋转运动** | 绕固定主轴匀速（或衰减）自转 | ✅ 已实现并验证 |

### 1.3 明确不在本期范围

- 软体 / 形变物体（soft body、tet 网格、Neo-Hookean）
- 多物体交互、碰撞、堆叠（Jenga、台球等上游场景）
- 外力施加（force / torque / impulse）
- PBR 纹理贴图随机化（HDRI 光照**已启用**，但物体/地面不贴图）

## 2. 调研结论

### 2.1 上游管线构成

PhyCo-Sim 本质是 **Kubric（Google Research）的一个改造分支**，仓库内 `kubric/` 是 vendored 的完整框架。运行链路：

```
Kubric Scene（物体 + 相机 + 光照）
        ↓
PyBullet 物理积分（DIRECT 无头模式，240 Hz 子步）
        ↓
逐帧位姿写入 Blender 关键帧（keyframe_insert）
        ↓
Blender/Cycles 渲染 → EXR 多层 → 后处理拆成 rgba / depth / segmentation
        ↓
metadata.json + 视频
```

**关键点**：物理与渲染**解耦**。PyBullet 只负责算出每帧位姿，出图靠 Blender 按关键帧求值。
因此只要给定一条轨迹（无论来自求解器还是解析式），渲染与标注链路完全一致。

### 2.3 上游方案在本机的三项硬性不兼容（已定位并解决）

| # | 问题 | 上游做法 | 本机实际 | 解决方案 |
|---|---|---|---|---|
| 1 | **Blender 版本** | 固定 Blender 3.4 + `bpy` wheel | 本机 Blender 5.2（Python 3.13）；`bpy` 无 Windows wheel，且 4.x 起 `bpy.ops.import_scene.obj` 被移除、Principled BSDF 插槽改名 | **独立部署 Blender 3.4.1** 于 `tools/runtime/`，全程 `blender.exe --background --python` 驱动 |
| 2 | **pybullet 无 Windows wheel** | Linux manylinux wheel | PyPI 上 pybullet **无任何** Windows 构建 | 取 **conda-forge `pybullet 3.25` cp310 win_amd64** 扩展模块 |
| 3 | **`verbose=False` 崩溃** | Kubric 默认走 `RedirectStream` | Windows 上 `os.dup2` 重定向 Blender 自有 stdout → `EXCEPTION_ACCESS_VIOLATION` | 强制 `verbose=True` |

> 隐蔽问题：`pip install OpenEXR` 默认装 3.4.x，与 Blender 3.4 链接的 OpenEXR 运行时不兼容，
> **必须锁定 `OpenEXR==3.2.3`**，否则读 EXR 时崩溃（已复现：3.2.7 与 3.4.15 均崩，3.2.3 正常）。

### 2.4 物理引擎的重要限制（直接决定方案选型）

Kubric 加载 URDF 时固定使用 `useMaximalCoordinates=True`。在该模式下，本机 pybullet 构建：

- `changeDynamics(...)` **返回成功但静默失效**（阻尼/摩擦仍为默认 0.01 / 0.5），且调用后**物体被冻结**；
- URDF 中的 `<dynamics damping=... friction=.../>` 同样**被忽略**。

**实测证据**（三组对照，各步进 60 子步，初速 3.0 m/s）：

| 工况 | 处理 | 位移 |
|---|---|---|
| 基线（仅通过 trait 设初速） | 无 `changeDynamics` | **0.750 m** ✅ |
| 设初速后调用 `changeDynamics(linearDamping=1.2)` | 有 | **0.000 m** ❌ |
| URDF 内嵌 `<dynamics damping="1.2">` | 有 | 3.0 m/s 恒定，阻尼仍为 0.01 ❌ |

**结论**：本机环境下**无法通过求解器参数控制阻尼**，因此三类运动全部采用**解析轨迹 + 关键帧**。
这不损失标注质量——解析解的物理量比求解器回读**更精确**，且完全可复现（见 §6 验证表）。

## 3. 技术方案

### 3.0 通用标注语义（重要）

三个场景的 `frames[].<object>.position` 一律标注**质心（center of mass）**在世界系中的位置——
这是物理上有意义的量。但网格并非以自身原点为中心（例如球的顶点位于局部 `z ≈ 1.0`，
恰好等于其 URDF `<inertial><origin>`）。因此写入关键帧时做一次换算：

```
mesh_origin_world = com_world − R(quaternion) · (scale · mesh_local_com)
```

`metadata.json` 的 `object_extent` 段完整记录 `mesh_local_min/max/com` 与相对质心的半尺寸，
使标注可被第三方独立复算。相机取景也以质心为基准。

### 3.1 运动 A：固定圆周运动

**定义**：物体质心沿半径 `R` 的圆做匀速圆周运动，同时绕圆法线自转。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--radius` | 1.2 m | 圆半径 |
| `--period` | 2.0 s | **转一圈所需时间**（主控物理参数） |
| `--plane` | `z` | 圆所在平面的法线（`z` = 水平圆） |
| `--spin_per_orbit` | 1.0 | 每公转一圈自转圈数 |
| `--height` | 0.9 m | 圆心离地高度 |

**导出物理量**（解析式，逐帧精确）：

```
θ(t) = ω t                     ω = 2π / period
p(t) = c + R·(cosθ, sinθ)      位置（质心）
v(t) = R·ω·(−sinθ, cosθ)       切向速度，|v| = Rω
a(t) = −R·ω²·(cosθ, sinθ)      向心加速度，|a| = Rω²
```

默认参数下：`ω = π rad/s`，`|v| = 3.77 m/s`，`|a| = 11.84 m/s²`。

### 3.2 运动 B：阻尼运动

**定义**：物体以初速 `v₀` 出发，仅受线性黏性阻尼，速度按指数衰减。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--speed` | 3.0 m/s | 初速 v₀ |
| `--linear_damping` | 1.2 s⁻¹ | 衰减率 k；**总位移 = v₀/k** |
| `--angular_damping` | 1.5 s⁻¹ | 角速度衰减率 |
| `--spin_rate` | 6.0 rad/s | 初始自转角速度 |
| `--direction` | 0° | 初速方向（XY 平面内） |

**模型与导出物理量**：

```
v(t) = v₀·e^(−kt)                       速度
x(t) = x₀ + (v₀/k)·(1 − e^(−kt))        位置（渐近位移 v₀/k）
a(t) = −k·v(t)                          加速度
ω(t) = ω₀·e^(−k_a t)                    角速度
θ(t) = (ω₀/k_a)·(1 − e^(−k_a t))        姿态角
E_k(t) = ½v(t)²                         动能，按 e^(−2kt) 衰减
```

起点自动设为 `x₀ = −½·(v₀/k)`，使整段运动在画面中居中。

**自校验**：生成后对 `ln v(t)` 最小二乘拟合反推 k。实测 `k_fit = 1.2000000000000013`，
相对误差 `1.1e-15`（机器精度），`R² = 1.0`。

### 3.3 运动 C：旋转运动（V1.1 新增）

**定义**：物体绕穿过自身质心的固定主轴旋转。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--spin_axis` | `z` | 旋转主轴（`x`/`y`/`z`，即惯性主轴） |
| `--spin_period` | 4.0 s | 转一圈所需时间 |
| `--spin_damping` | 0.0 s⁻¹ | 角速度衰减率；`0` = 匀速自转 |

**模型与导出物理量**：

```
匀速：  θ(t) = ω₀ t
衰减：  ω(t) = ω₀·e^(−kt)，  θ(t) = (ω₀/k)·(1 − e^(−kt))
```

**额外物理标注**（从 URDF `<inertial>` 读回真实惯量）：

```
I_axis          绕主轴的主惯性矩（ixx/iyy/izz）
L = I·ω         角动量
E_rot = ½Iω²    转动动能
```

实测：`brick_box` 的 `I_zz = 0.006649`、`jenga` 的 `I_yy = 0.001950`，与 URDF 一致。

> **物体选择注意**：球形物体自转在视觉上不可分辨（球对称），因此旋转场景**排除球体**，
> 只使用 `brick_box` / `brick` / `brick_tall` / `jenga` / `wall` 等非球对称网格。

### 3.4 光照：HDRI（V1.1 变更）

默认使用 `models/hdri_haven/` 中已缓存的 4 个 4K HDRI，按 `--seed` 播种随机选取
（`--hdri_random`），提供真实环境光与背景多样性，且**完全离线**（改写 manifest 的 `data_dir`
指向本地缓存）。可用 `--no_hdri` 退回解析光照（平行光 + 纯色背景）。

实测 HDRI 生效证据：背景像素均值 194.4（纯黑背景应接近 0），单帧含 1185 种不同颜色。

**耗时实测**（单进程 CPU Cycles，本机 Intel i7-1260P / 16 线程，**无 NVIDIA GPU**）：

| 分辨率 | 采样 | 光照 | 场景 | 实测单帧 | 单条 96 帧 |

| 480×270 | 32 | 解析光 | 阻尼 | 2.40 s | 3.8 min |

> 渲染耗时近似与「像素数 × 采样数」成正比；HDRI 比解析光慢约 10–40%。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| CPU 渲染耗时长 | 全量 36 条约 5–7 h | ① `--workers 3` 并行；② 可降采样/降分辨率重跑；③ HDRI 可关（`--no_hdri`） |

| # | 事项 | **决议** |
