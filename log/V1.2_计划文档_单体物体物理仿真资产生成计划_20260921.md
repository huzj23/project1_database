## 1. 目标与范围

### 1.1 总目标

产出**带逐帧物理标注的视频资产**，用于物理世界模型 / 可控运动生成模型的训练与评测。

### 1.2 本期范围（已确认）

**无交互环境**（场景中只有一个运动物体，除静态地板外无其他动力学物体、无碰撞参与）下，
生成单个物体的三类运动：

| 编号 | 运动类型 | 物理含义 | 状态 |
|---|---|---|---|
| A | **固定圆周运动** | 物体沿固定圆形轨迹匀速运动，含自转 | ✅ 已验证 |
| B | **阻尼运动** | 速度按指数规律衰减的黏性阻尼运动 | ✅ 已验证 |
| C | **旋转运动** | 绕固定主轴匀速（或衰减）自转 | ✅ 已验证 |

### 1.3 不在本期范围

- 软体 / 形变物体（soft body、tet 网格、Neo-Hookean）
- 多物体交互、碰撞、堆叠
- 外力施加（force / torque / impulse）
- PBR 纹理随机化（HDRI 光照已启用，物体/地面不贴图）

### 2.5 服务器环境四项硬性坑位（均已解决）

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | Blender 无法启动：`libxkbcommon.so.0: cannot open shared object file` | CentOS 7 未安装该库 | **不装系统包**（会污染共享机器），改为下载 CentOS 7 RPM 并**只提取 `.so` 到工作区** `tools/runtime/lib/`，用 `LD_LIBRARY_PATH` 指向；并按 ELF `SONAME` 建立符号链接 |
| 2 | pip 全部报 `CERTIFICATE_VERIFY_FAILED` | Blender/bpy 自带 CPython **没有 CA 信任库**（`ssl.get_default_verify_paths()` 返回 `None`） | 把系统 CA bundle 复制进工作区 `tools/runtime/ca-bundle.crt`，导出 `SSL_CERT_FILE` / `PIP_CERT` |
| 3 | 部分 HTTPS 请求随机 `403 Forbidden` | **tmux 服务器是很早以前由别的会话启动的，环境里没有代理变量**；直连时部分站点被拒 | 新增 `tools/server_env.sh`，显式导出 `http_proxy/https_proxy=http://127.0.0.1:7890`，所有脚本先 `source` 它 |
| 4 | `pypi.tuna.tsinghua.edu.cn` 恒返回 403（任何 UA） | 该镜像经本机代理被拦截 | 改用 `pypi.org`（实测 200），并将结论写死在 `server_env.sh` 注释中 |

### 2.6 【重要】GPU 渲染不可用——实测结论

用户要求"使用空闲的 GPU 完成仿真计算"。经系统实测，**本管线无法使用 GPU 渲染**，
依据如下（均为可复现的确定性结果，非偶发）：

**（1）GPU + 深度通道 = 必然段错误**

| 图层组合 | GPU 渲染 | CPU 渲染 |
|---|---|---|
| `image,segmentation` | ✅ 正常 | ✅ 正常 |
| `image,depth` | ❌ SIGSEGV (139) | ✅ 正常 |
| `depth`（单独） | ❌ SIGSEGV (139) | ✅ 正常 |
| `image,segmentation,depth` | ❌ SIGSEGV (139) | ✅ 正常 |

复现率 4/4（确定性）。崩溃发生在渲染完成之后、读取多层 EXR 的 `Depth.V` 通道时。
深度图是本数据集**必需的标注**，因此 GPU 渲染路径不可用。

**（2）即使可用，GPU 也无明显收益**

| 配置 | GPU | CPU |
|---|---|---|
| 768×432 / 64spp | 2.68 s/帧 | 3.07 s/帧 |
| 768×432 / 32spp | 2.61 s/帧 | 2.80 s/帧 |

GPU 仅快约 **13%**——因为每帧开销由 EXR 写盘、合成与场景同步主导，而非光线追踪。
而本机有 **104 核**，并行 CPU 工作进程的收益远大于这 13%。

**结论**：采用 **CPU 渲染 + 多进程并行**（`WORKERS` 个进程，每进程 `104/WORKERS` 线程，
避免线程超订）。GPU 保持空闲，不影响其他使用者。

> 该结论已写入 `tools/server_env.sh` 与 `tools/run_server.sh` 的注释，
> `KUBRIC_USE_GPU` 默认 `false`，避免后续误用。

### 2.7 深度层 segfault 的根因与修复（CPU 路径）

CPU 渲染下仍偶发深度层崩溃，最终定位为**顺序敏感的堆损坏**：

- Kubric 的 `read_channels_from_exr()` 用 `np.frombuffer()` 在**临时 EXR 字节缓冲**上建视图；
- 即便先做 `np.array(..., copy=True)`，**在其之后再分配 rgba/segmentation 的大数组**，
  会让深度数组的底层缓冲失效；
- 之后任何 numpy 访问都会 SIGSEGV（表现为崩在 `prepare_depth_mm` 里，且无 Python 栈）。

修复（`phyco_common.py`）：

1. `_owned()` 改为 **`tobytes()` 往返**，生成无 `base`、无共享所有权的私有缓冲；
2. 三个图层的准备顺序固定为 **depth → rgba → segmentation**（深度最先，最脆弱）；
3. 所有 numpy 处理在**任何 OpenCV 编码调用之前**完成。

修复后重跑 12 次（含生产规格）**全部通过**。

## 3. 技术方案

### 3.0 通用标注语义

`frames[].<object>.position` 一律标注**质心（center of mass）**在世界系中的位置。
网格并非以自身原点为中心（球体顶点位于局部 `z ≈ 1.0`，恰为其 URDF `<inertial><origin>`），
因此写入关键帧时做换算：

```
mesh_origin_world = com_world − R(quaternion) · (scale · mesh_local_com)
```

`metadata.json` 的 `object_extent` 段记录 `mesh_local_min/max/com` 与相对质心的半尺寸，
便于第三方独立复算。相机取景同样以质心为基准。

### 3.1 运动 A：固定圆周运动

| 参数 | 默认 | 说明 |
|---|---|---|
| `--radius` | 1.2 m | 圆半径 |
| `--period` | 2.0 s | 转一圈所需时间（主控物理参数） |
| `--plane` | `z` | 圆平面法线 |
| `--spin_per_orbit` | 1.0 | 每公转一圈自转圈数 |

```
θ(t) = ω t                     ω = 2π / period
p(t) = c + R·(cosθ, sinθ)
v(t) = R·ω·(−sinθ, cosθ)       |v| = Rω
a(t) = −R·ω²·(cosθ, sinθ)      |a| = Rω²
```

默认：`ω = π rad/s`，`|v| = 3.77 m/s`，`|a| = 11.84 m/s²`。

### 3.2 运动 B：阻尼运动

| 参数 | 默认 | 说明 |
|---|---|---|
| `--speed` | 3.0 m/s | 初速 v₀ |
| `--linear_damping` | 1.2 s⁻¹ | 衰减率 k；总位移 = v₀/k |
| `--angular_damping` | 1.5 s⁻¹ | 角速度衰减率 |

```
v(t) = v₀·e^(−kt)
x(t) = x₀ + (v₀/k)·(1 − e^(−kt))
a(t) = −k·v(t)
ω(t) = ω₀·e^(−k_a t)
E_k(t) = ½v(t)²                 按 e^(−2kt) 衰减
```

起始点自动设为 `x₀ = −½·(v₀/k)`，使运动在画面中居中。
**自校验**：对 `ln v(t)` 拟合反推 k，实测相对误差 `1.1e-15`，`R² = 1.0`。

### 3.3 运动 C：旋转运动

| 参数 | 默认 | 说明 |
|---|---|---|
| `--spin_axis` | `z` | 旋转主轴（惯性主轴） |
| `--spin_period` | 4.0 s | 转一圈所需时间 |
| `--spin_damping` | 0.0 | 角速度衰减率；0 = 匀速自转 |

额外物理标注（从 URDF `<inertial>` 读回真实惯量）：`moment_of_inertia`、`angular_momentum = Iω`、
`rotational_energy = ½Iω²`。实测 `brick_box` 的 `I_zz = 0.006649`、`jenga` 的 `I_yy = 0.001950`。

> **物体选择**：球形物体自转在视觉上不可分辨，故旋转场景**排除球体**，
> 仅用 `brick_box` / `brick` / `brick_tall` / `jenga` / `wall`。

### 3.4 光照

默认从工作区内缓存的 4 个 4K HDRI 中按 seed 随机选取（完全离线），提供真实环境光与背景多样性。

### 3.5 输出规格

| 文件 | 内容 | 格式 |
|---|---|---|
| `rgba_%05d.jpg` | RGB 帧 | JPEG q95 |
| `segmentation_%05d.png` | 实例分割掩码 | uint16 PNG（0=背景，1=地板，2=物体） |
| `depth_%05d.png` | 深度图 | **uint16 PNG，单位毫米**，0=无效 |
| `metadata.json` | 完整物理标注 | JSON |
| `rgb.mp4` / `segmentation.mp4` / `depth.mp4` | 视频 | H.264 (libx264, crf 18) |
| `qa_contact_sheet.jpg` | 人工质检缩略图（非数据集载荷） | JPEG |
