## 0. 本阶段交付目标

### 目标 A：新增真实资产

- 首批规范化并验证 **8–12 个新刚体物体**；至少来自 YCB、ABO、Poly Haven 中的两个来源。
- 首批规范化并验证 **2 个 HF 当前没有的真实三维场景**：优先 `The Shed` 与 `Italian Flat`，兼容性失败时依次用 `Cozy Kitchen`、`Hidden Alley` 替换。
- 每个资产具有来源、许可、原始 SHA256、真实尺度、初始姿态、visual、collision、物理参数和固定 seed 预览证据。
- 不以 HDRI 代替三维场景，不把空旷影棚或纯背景图作为最终环境。

### 目标 B：场景可交互

- 先以已有 `replicad_apartment` 做全场景被动碰撞试点，再迁移到新场景。
- 地面、墙、台阶、桌、柜、椅等固定内容在 PyBullet 中注册为 `mass=0 / useFixedBase=True` 的静态体。
- 被仿真物体撞到家具或墙时，PyBullet 轨迹、`collisions.json` 与 Blender 画面一致。
- 本阶段不让家具成为动态物体；“可交互”仅指演员可与静态/被动场景发生真实接触。

### 可选目标 C：软体可行性

- 只做一个工程探针和一个真实视觉候选，不影响 A/B 主线。
- 在完成逐顶点仿真结果写出与 Blender 回放以前，不把任何柔软外观模型作为软体交付。

## 1. 不可回退的工程规则

1. **真求解器**：Scenario 只提供初始状态、外力和材料参数，后续状态全部由 PyBullet 积分。
2. **真实视觉**：不使用纯色原型体代替正式物体；视觉模型必须有来源与许可。
3. **单一物理真相**：Blender 只负责回放和渲染，不运行第二套刚体/软体求解器。
4. **不篡改场景**：不得增加补丁地面、遮挡物、影棚墙或临时道具；不得删除原场景内容来方便相机。
5. **作者光照优先且默认唯一**：保留作者灯光和 World；本阶段不自动添加 Sun/Area/默认灯。原光照不足时先拒绝该场景并提交用户裁定，而不是静默补光。
6. **真实碰撞几何**：支撑面和障碍碰撞必须来自原模型；不能用跨越楼梯、洞口或家具的巨大 box 假装地面。
7. **先校验再渲染**：物理、穿透、碰撞、相机遮挡、主体占比和灯光来源全部通过后才允许正式渲染。
8. **Git/HF 分工**：代码、YAML、许可、碰撞代理、测试和文档进 Git；source、visual、纹理、`.blend` 与数据集大文件进 HF。

## 2. “全部设为被动项”的正确落地方式

用户记忆中的做法在物理语义上是正确的，但要区分 Blender 与 PyBullet：

- 在 Blender 中把物体设为 Passive，只会影响 Blender 自己的 Rigid Body World。
- 本项目铁律要求 Blender 不运行第二个求解器，因此**仅设置 Blender Passive 不会让 PyBullet 碰到这些物体**。
- 当前后端只加载 `maps.yaml` 选中的 surface collision，所以未登记的墙体和家具仍只是视觉几何。

本项目的正确实现为：

```text
原始 .blend/.glb
  -> visual/scene.blend（保留作者材质、灯光、World）
  -> static_colliders/（从原场景对象生成静态碰撞）
  -> MapSpec.static_colliders
  -> PyBullet useFixedBase=True / mass=0
  -> actor 与场景接触求解
  -> Blender 回放同一 actor 轨迹
```

Blender 文件可额外保留 Passive 标记，方便人工检查和与学长资产约定对齐，但它不是运行时物理来源。

## 3. 工作流 A：新刚体物体

### A1. 候选筛选

首批候选：

- YCB：木块、锤子、电钻、挂锁、扳手、饼干盒、芥末瓶、金属杯/碗；
- Poly Haven：手电筒、复古行李箱、喷漆罐、木凳、木斧、黄铜花瓶；
- ABO：从 GLB 元数据中筛选 20 个硬塑料、金属、陶瓷和硬纸盒商品，再选 6–8 个。

硬门槛：

- 许可必须为 CC0、CC BY 或经确认可在私有 HF 再分发的许可；
- 排除 UNKNOWN、编辑限制不清、仅允许渲染但不允许再分发原模型的资产；
- 排除布料、海绵、软包装、毛绒、液体、带缆线物体和未处理铰接机构；
- 排除单位/尺度不可确认、严重破面、纹理缺失、法线错误或依赖不可用插件的资产；
- 单一 convex hull 会封住功能空腔的杯/碗/花瓶，必须能生成 compound collision，否则淘汰。

### A2. 规范化

每个资产执行：

1. 原下载不改动放入 `source/`；记录 URL、作者、许可、下载日期、SHA256。
2. 禁止自动执行下载 `.blend` 内嵌脚本；用 factory startup/headless 检查。
3. 烘焙世界变换、处理镜像法线、居中、转为真实米制尺度。
4. 确定普通静置姿态，并用同一四元数驱动 Scenario、PyBullet 与 Blender。
5. 基础几何可用 primitive；其他物体生成 ≤512 面低模碰撞；凹体使用 compound。
6. 写入真实 `mass_range`，依据制造商规格、YCB 实物数据或材料密度估算，禁止沿用无依据的克级数值。
7. 记录 size、support height、footprint radius、bounding radius 与碰撞 SHA256。

### A3. 单物体验收

- visual/collision AABB 逐轴对齐，中心和初始姿态一致；
- 静置 5 秒无悬空、无持续抖动、无 >2 mm 稳态穿透；
- 固定 seed 的自由落体或滚动测试符合物体语义；
- 空心体能容纳探针球，证明碰撞体没有封死空腔；
- 生成 5 视图转台预览和资产接触表，不通过则不登记 `allowed_scenarios`。

## 4. 工作流 B：新真实场景

### B1. 首批场景顺序

1. `Poly Haven The Shed`：CC0、道具丰富，优先验证完整场景与静态碰撞拆分。
2. `Blender Italian Flat`：CC BY、真实感室内，优先验证作者灯光和大型 `.blend`。
3. 失败替补：`Cozy Kitchen`，随后是 `Hidden Alley`。
4. `Pine Forest` 只在室内两项完成后尝试；不平地表和植被遮挡使其风险更高。

### B2. 原场景审计

在任何规范化处理前记录：

- Blender/文件版本、对象数、mesh 数、材质数、贴图数、灯光数量和类型、World；
- 相机、实例集合、Geometry Nodes、代理对象、隐藏对象与负缩放；
- 场景总包围盒、真实单位、主要地面/桌面/台阶高度；
- 原始 SHA256 和许可文件；
- 一张不改灯、不加物体的基线渲染。

### B3. 视觉规范化

- 生成 packed `visual/scene.blend`，所有纹理自包含；
- 保留作者灯光在 `environment_lighting`，保留作者 World 为 `environment_world`；
- 不新增灯、补丁平面、cyclorama 或装饰物；
- linked collection 实体化后再合并 visual，但保留对象到静态碰撞体的映射表；
- 规范化前后固定相机渲染做像素/结构对照，确认没有内容丢失。

### B4. 场景质量闸门

| 检查 | 通过标准 |
|---|---|
| 灯光来源 | `source_blend`；数量和类型与源场景审计一致；supplemental=0 |
| 曝光 | 非黑、非大面积过曝；亮度分位数进入人工可审查范围 |
| 场景完整性 | 无新增补丁地面/灯/墙；无误删家具、材质、贴图 |
| 生活感 | 主机位可见多个日常参照物，非空房/纯影棚；由 contact sheet 人工确认 |
| 主体占比 | 全程完整入镜；最小投影宽度 ≥5%，建议中位数 10–22%，最大不超过 35% |
| 遮挡 | 主体有效可见比例 ≥85%；相机射线不被近距离家具/墙体持续遮挡 |
| 运动覆盖 | 轨迹关键点均在画面内，边缘留量 ≥3% 画宽 |
| 支撑面 | 来自原几何；每个 region 有射线/碰撞验证和 `verified_clear` 记录 |

任何一项失败，先换 region、相机方位或场景；不得通过删除家具、抬高地板或加灯来掩盖问题。

## 5. 工作流 C：全场景被动碰撞

### C1. ReplicaCAD 首个试点

优先利用现有 ReplicaCAD 的 76 个凸分解碰撞体、家具 URDF 和 scene instance：

1. 建立 `visual object -> collision asset -> world transform -> semantic name` 清单。
2. 将建筑外壳、墙、楼梯和固定家具分组；动态门/抽屉本轮锁定为固定姿态。
3. 为缺碰撞体的静态对象生成低模 collider；静态凹网格允许使用三角 mesh，动态 actor 仍必须 convex/compound。
4. 扩展 `MapSpec`，新增 `static_colliders`，每项包含 simulation path、位姿、缩放和实例名。
5. PyBulletBackend 在 actor 创建前加载所有 static collider，设置 `static=True`/`useFixedBase=True`。
6. `collisions.json` 增加被撞静态体的稳定实例名，便于证明“撞到了桌/墙/椅”。

### C2. 交互验证样例

至少完成三条固定 seed smoke：

- 滚动物体撞椅腿或柜体后改变速度/方向；
- 自由落体落在真实桌面而不是补丁盒体；
- 抛体撞墙或固定家具并产生可核对的接触事件。

验收：

- `collisions.json` 中出现对应静态实例；
- 最大穿透不超过现有 validator 门限，且接触后轨迹连续；
- PyBullet 轨迹与 Blender 画面逐帧一致；
- 移除该 static collider 后，同 seed 轨迹显著变化，作为反事实证明碰撞确实生效；
- 不得因为全量 collider 导致初始放置点被家具占用，SurfaceSampler 必须继续执行净空验证。

### C3. 迁移到新场景

ReplicaCAD 通过后，把同一 `static_colliders` 接口应用到 The Shed/Italian Flat。禁止为每个场景写专用物理后端；场景差异只存在于资产 manifest、碰撞文件和 maps 配置。

## 6. 工作流 D：软体可行性支线

### D1. 两级验证

1. 用 Bullet 官方 bunny/torus 完成 `loadSoftBody -> getMeshData -> 地面碰撞 -> 逐顶点序列` 工程探针。
2. 用 Poly Haven `Throw Pillows 01` 中拆出的单个枕头做真实视觉候选。

### D2. 进入正式资产前的硬门槛

- 表面网格闭合、无自交，或能稳定生成 VTK/四面体体网格；
- PyBullet 软体参数在固定步长下可复现，不爆炸、不穿地；
- 每帧逐顶点位置能写出，并在 Blender 中以 mesh cache/morph 方式回放；
- depth、segmentation、碰撞标注和可见形变均能验证；
- 渲染画面中的顶点与物理导出的顶点误差在容忍范围内。

任一门槛未过，只保留调研记录，不进入数据生成计划。

## 7. Git 与 HF 工作流

### 7.1 Git

- `main` 保持可运行；每个来源/场景使用独立分支，例如 `asset/ycb-rigid-pilot`、`scene/polyhaven-shed`、`feature/static-colliders`。
- 每个资产至少三个提交点：来源/许可登记、规范化 visual/collision 清单、固定 seed 验证结果。
- Git 跟踪 `asset.yaml`、`license/`、`collision/`、代码、配置、测试和 log；不跟踪 visual/source/数据集/运行时。
- 每次服务器运行前推送 Git commit；metadata 记录 Git commit、资产 SHA256 和 HF revision。

### 7.2 HF

- 大文件上传继续使用合并式驱动，上传前下载并合并远端 manifest，禁止整表覆盖。
- 先补传现有 5 个 GSO，再上传新资产。
- 每次上传后做全新目录 round-trip：下载、AssetManager 枚举、材质解析、碰撞存在性和一帧渲染。
- UNKNOWN 许可资产永不上传；CC BY/SA/NC 必须显式白名单并在数据集卡片中说明义务。

## 9. 首轮具体动作

1. 提交当前 Git 基线与服务器最终代码备份。
2. 修正 5 个 GSO 的 `source/`、质量和 manifest，执行 HF 增量同步。
3. 下载 YCB 的木块、锤子、电钻、饼干盒，以及 Poly Haven 手电筒/行李箱作为第一批 6 个刚体。
4. 下载 The Shed scene file，只做源场景审计和不改灯基线渲染，不立即生成正式数据。
5. 为 ReplicaCAD 生成 `static_colliders` 实例清单，并先实现“滚动物体撞椅腿”的最小闭环。
6. 并行做 Bullet bunny 逐顶点导出探针；未通过时不影响刚体/场景主线。
