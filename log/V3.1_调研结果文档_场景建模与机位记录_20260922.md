## 1. 场景构建方式（全部场景通用）

### 1.1 室内场景（ReplicaCAD，5 个）

```text
1. 导入 stages/<stage>.glb          （建筑外壳：地板/墙/门/楼梯）
2. 读 configs/scenes/<layout>.json  （作者布置的家具布局，含每个道具的平移+朝向）
3. 逐道具导入 objects/<name>.glb，按布局放置
   → 坐标映射：habitat(x,y,z) → blender(x, -z, y)
4. 读 configs/lighting/<declared>.lighting_config.json
   → 创建 7 盏点光源，强度 × 60（Habitat 单位 → Cycles 瓦特）
5. 导出 visual/scene.blend
   → 所有网格 join 成单一对象 "environment"（Kubric 要求 selected==1）
   → 灯放进独立 collection，不参与选择
```

**关键参数**：

| 项 | 值 |
|---|---|
| 灯光缩放 | ×60 |
| 环境光（ambient） | `(0.50, 0.50, 0.53)` |
| 背景色 | `(0.60, 0.68, 0.80)` |
| 分辨率 | 1920×1080 |
| 采样 | 48 spp + 降噪 |

**为什么必须用 `scene.blend` 而非 `.glb`**：glTF 往返转换会把场景几何丢到几百米外（实测 765 m），且不携带作者灯光。

### 1.2 室外场景（HDRI 背景 + PBR 地面）

```text
1. 4K HDRI 全景作为世界背景（bg_strength=1.0）
   同时提供环境光（strength=0.85~0.9，压低以保住接触阴影）
2. 自建 PBR 地面（concrete_floor_worn_001，uv_scale=6，6 m 见方）
3. 一盏 DirectionalLight 作主光（强度 2.4~2.6）投出接触阴影
4. 主体置于地面
```

**HDRI 全景本身没有地面**——地面完全由我们的平面提供，这是当前**主要的不真实来源**（见 §4）。

## 3.5 转盘资产（新增，程序生成）

**资产调研结论：我们没有转盘素材。**

| 来源 | 结果 |
|---|---|
| GSO（1033 个物体） | **无转盘**。只有 DVD 碟片、花盆底碟、托盘、篮子 |
| Poly Haven（521 个模型） | **无转盘** |
| ReplicaCAD | 无 |

**因此程序化生成**——这同时也是更好的工程选择：

| 项 | 值 |
|---|---|
| 路径 | `assets/objects/turntable/` |
| 几何 | URDF `<cylinder radius="0.55" length="0.03"/>` |
| 碰撞 | **精确圆柱原语**（非多面体凸包，旋转平滑无抖动） |
| 质量 | 1.0 kg（URDF 标称 2.0，Kubric 加载后实测 1.0） |
| 许可证 | CC0（本项目生成，无第三方内容） |

### 转盘的物理驱动方式（关键）

```text
转盘 = 动力学体（static=False）
每物理步：
  1. 读当前朝向
  2. 钉住位置（防止漂移），朝向原样传回
  3. resetBaseVelocity(角速度 = ω)   ← 这就是"电机"
  4. stepSimulation()
```

**"物体绕圈"是接触+摩擦的结果，不是脚本写死的路径。** 这正是用转盘替代"动画画圆"的意义。

### 实测结果（240 Hz 步进，3.0 s）

| ω (rad/s) | 物体转过 | 转盘转过 | 理论值 | **滑移比** | 半径 | 是否在盘上 |
|---|---|---|---|---|---|---|
| **0.50** | **83.6°** | **84.2°** | 85.9° | **0.99** | 0.300 恒定 | ✅ |

**滑移比 0.99 = 物体以转盘 99% 的速度被携带。** 半径全程保持 0.300 m，说明是**绕轴公转而非滑出盘外**。

### 排查中发现的三个真实陷阱

| # | 陷阱 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | `static=True` | Kubric 传 `useFixedBase=True`，**转盘被焊死**，永远不转 | 转盘必须 `static=False` |
| 2 | `changeDynamics(mass=0)` | PyBullet 里 mass=0 = **静态体**，设了角速度也不动 | 保持动力学体，每步重设角速度当"电机" |
| 3 | 步进频率 | Kubric 客户端按 **1/240 s** 步进；若按视频帧步进，一切看起来慢 10 倍 | 每个视频帧步进 `physics_fps / video_fps` 次 |

> 第 3 条曾让我误判"物理不对"——实际是 47 步只推进了 0.196 s 而非 1.96 s，角度（13.5° vs 1.2×0.196）**完全吻合**，反而证明了物理是对的。

### 转盘的材质与摆放（2026-09-22 追加）

**材质选型用测量而非猜测。** 同一转盘渲染四种木材并测量 R/B 与木纹强度：

| 木材 | R/B | 木纹 (Laplacian var) | 判定 |
|---|---|---|---|
| `cherry_veneer` 樱桃木 | 1.40 | 14.8 | ❌ 偏淡 |
| `american_walnut_veneer` 胡桃木 | 1.05 | 57.2 | ❌ 发灰 |
| **`dark_wood`** | **2.00** | **49.8** | ✅ **采用** |

最终成品实测 **R/B = 1.83、R/G = 1.58**，落在红木区间（R/B 1.6–2.6、R/G 1.3–1.8）内。

> 注：给贴图材质"染色"（改 Principled 的 Base Color 默认值）**无效**——贴图的 Image Texture 已接到 Base Color 上，会覆盖纯色值。要染色必须插 Mix 节点。

**摆放**：放在 `frl_apartment_table_01` 桌面上（桌面 z = 0.758 m，跨度 1.40 × 0.85 m）。转盘半径定为 **0.30 m**——最初用 0.55 m（直径 1.1 m）时，盘子**悬在 0.85 m 宽的桌子外面**，一眼就假。

### ⚠️ 重大发现：Blender 里没有关键帧 = 所有帧都是同一张静图

第一次渲染 4 帧（f00/f08/f16/f24）得到的是**四个字节完全相同的 PNG**：

```text
mahogany_f00.png  MD5=DA6B7B8E482F64C9
mahogany_f08.png  MD5=DA6B7B8E482F64C9
mahogany_f16.png  MD5=DA6B7B8E482F64C9
mahogany_f24.png  MD5=DA6B7B8E482F64C9
像素差 max=0  mean=0.000
```

**原因**：PyBullet 里物体确实在动，但我只把轨迹存在了 Python 变量里，**从未告诉 Blender**。Blender 没有动画数据，渲染任何帧都输出同一个静态姿势。

**修法（正是导师 pipeline 的核心规则）**：把 PyBullet 的轨迹**转录为 Blender 关键帧**再渲染——

```python
for f, (ap, aq) in enumerate(traj):        # traj 来自物理引擎
    bpy.context.scene.frame_set(f)         # 注意：kb.Scene 没有 frame_set
    ao.location = ap
    ao.rotation_quaternion = (aq[3], aq[0], aq[1], aq[2])
    ao.keyframe_insert("location", frame=f)
    ao.keyframe_insert("rotation_quaternion", frame=f)
```

修复后 4 帧真正不同：

| 对比 | 最大像素差 | 变化像素数 |
|---|---|---|
| f08 vs f00 | 179 | **1,240,023** |
| f16 vs f00 | 188 | **1,304,644** |
| f24 vs f00 | 186 | **1,413,039** |

> **这正是"绝不用预先规定的轨迹"的落地方式**：轨迹仍由物理引擎（接触+摩擦）产生，我们只是把**结果**转写成关键帧让 Blender 回放。

## 4. 已知问题与待改进

| # | 问题 | 影响 | 建议做法 |
|---|---|---|---|
| 1 | **室外地面材质与环境不匹配** | 街道上铺混凝土、公园里铺混凝土——**接缝感明显**，这是当前室外最大破绽 | 按环境配地面材质：街道→沥青、公园→草地、体育场→球场草皮 |
| 2 | HDRI 无视差 | 相机移动时背景不随之变化（全景图特性） | 运动幅度小的场景可接受；需要视差时改用真三维场景 |
| 3 | 室内方位 255° 钻墙 | sc0 该方位出黑图 | 机位前做视线探测预筛 |
| 4 | 分割图层全 0 | 影响标注交付与自动评分 | 待修 |
| 5 | 渲染 scratch 陈旧帧 | **已修复**（`purge_stale_frames`） | — |

**结论（回答"室外会不会像室内一样空旷"）**：

- **俯视机位下：会**，而且更严重（大片自建地面 + 环境只露一条边）
- **平视地平线机位下：不会**，五个环境都能读出"这是什么地方"，其中 `orlando_stadium`（看台+球场）和 `german_town_street`（车道线）辨识度最高
- **但有一个室内没有的新问题**：地面材质与环境不匹配，这是下一步要修的
