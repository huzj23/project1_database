# 04：多刚体求解、时间一致性与因果验证

前置：01、02通过；03提供主选物体和至少一个真实静态表面。目标是一个可复用N刚体接口，供05–08共用。不是制作三个独立脚本。

## 1. 实现顺序

1. 按02扩展resolved多体配置与结果类型，所有asset/map由管理器解析后传入。
2. 建立普通active/passive世界，每个instance登记唯一body ID；导入static局部网格、目标和触发物。
3. 实现初始化、预静置、单次触发、固定步长积分、全体状态/接触记录。
4. 实现几何/稳定/因果/禁入/越界验证，在任何Blender正式渲染之前输出PASS/FAIL和原因。
5. 扩展renderer/IO只回放多体结果，先输出一张正确初态图，再做真实两体样例。

现有转盘 `_drive_support` 会逐子步reset位置/速度；它是专门的驱动支撑逻辑，本轮不得复用。普通链目标全部从头就是可动刚体，不按预设时刻从被动切为主动，不在接触后施加补推。

## 2. 求解配置起点

| 参数 | 起点 | 改动条件 |
|---|---|---|
| video_fps | 24 | 必须整除physics_fps |
| physics_fps | 480 | 薄体/高速穿透或步长敏感升至960，再必要1920 |
| solver iterations | 150 | 检查收敛后可至300；不能代替减小dt |
| gravity | 9.81 m/s²向下 | 固定，不能为效果改重力 |
| restitution | 0.02–0.15 | 用明确材料理由和对照调整 |
| lateral friction | 0.3–0.7 | 起点，实际材质及PyBullet配对规则决定 |
| linear/angular damping | 0.01–0.05 | 同一实验固定，不能逐帧调 |
| rolling/spinning friction | 0.001量级起点 | 记录API值，不把它当已测物性 |

这些是调试范围，不是已测真实参数。使用 `getDynamicsInfo` 读回有效设置；接触配对时摩擦/恢复的组合规则应按安装版本源码/文档确认。

每步最大接触点运动量粗查 `(|v| + |ω|*R)*dt <= 0.1*t_min`，其中t_min是最薄相关碰撞厚度。违反时减步长/速度，并评估CCD；CCD是否适用必须通过穿透测试，不能仅打开选项就宣称解决。

## 3. 初始状态与单次触发

目标在无触发诊断世界中自由静置至少2秒，必要时5秒。稳态末0.5秒最大平移漂移 ≤2 mm、姿态漂移 ≤1°、无持续跳动。若薄小物体需要更严格容差，按尺寸收紧。初始接触穿深目标≤ `min(1 mm, t_min*5%)`；signed contact distance有margin误差，同时检查visual和真实几何。

正式世界初态由相同静置结果重建；触发物可自然释放落下，或只在t=0设置一次线速度/有限时长力，力的对象、起止时刻和积分必须记录。第一版优先自然下落或一次初速度。不能为每个目标分别设置发车时间。

对后续目标的“保持静止”是验证要求，不是强制冻结行为。保持它们自然受到重力和接触，让无触发对照证明稳定。

## 4. 接触、运动启动与倾倒事件

完整记录每物理子步动态物体状态与所有接触；不保留旧脚本的“最多100条接触”限制。所有body pair接触法向作用对称，方向应结合预接触运动和目标启动判定。

建议运动启动阈值：相对settled初态平移>2 mm或主轴姿态偏转>2°，且持续至少20 ms，并伴随线速度>0.02 m/s或角速度>0.1 rad/s。更小资产按尺寸调整，阈值必须在试验前固定并写入resolved_config。

多米诺倾倒使用物体本地竖直长轴与世界Z的夹角：超过50°并持续至少0.10秒。不能用绕竖轴转向50°冒充倒下。允许末端落地/支撑后停止；要求每一指定盒的倾倒事件发生。

传播 A→B 需同时满足：A已有上游触发或被指定为唯一触发物；A/B有效动态接触先发生；B此前近静止；B随后在约0.15秒窗口内发生可见响应；冲量估计/相对接近速度足以区别数值微接触；没有B上的外部控制或旁路触发。

原始接触可能反复，物体级图可能有回边，不强行篡改成DAG。把每个“首次启动传播事件”作为时间图节点，记录有序路径和所有额外接触。主路径时间在物理子步分辨率上严格增加；若多个传播同一步发生，细化步长或布局，不能人为排序。

## 5. 必须有的对照与反例

- 无触发：相同布局、质量、材料和时长，取消唯一触发初速度/移除触发物，仅改变这一因子；全部目标维持稳定。取消速度对自然落体不等于取消触发，应在诊断世界不放落体触发物。
- 断链：最终12盒链在中间缺一盒，例如box_006；保持其余位置和相同触发。前半链照常倒，后半链不启动。如果前一盒跨空隙打到下游，调整间距或明确另选可隔断环节，再重跑，不将旁路成功记为通过。
- 同种子重复：在同一软件/硬件栈跑3次，事件顺序完全一致，关键时刻差≤一个视频帧。跨平台不要求bitwise一致，分别报告。
- 步长敏感性：最终样例用480与960 Hz（或当前与一半dt）各跑一遍，传播顺序/成功链长一致；事件时差目标≤一个视频帧，超过则检查收敛并采用更细步长。
- 反例：重复ID、错四元数、初始穿透、没有碰撞但手动移动目标、断链仍全倒、缺目标轨迹，验证器必须拒绝。

静态地面可以传力但本轮保持固定，不产生可动支撑平台传播。无触发与断链对照是因果证据的一部分，不单凭有接触日志就宣称证明因果。

## 6. 限量调参

先检查尺度/坐标/碰撞，再调整布局，再物性，最后求解精度。一个attempt只改变一个已声明因素。每个场景初轮最多12次纯物理试验；分析后允许第二轮12次针对试验，不进行大渲染碰运气。

不要用异常质量、极低/极高摩擦、高反弹或几十m/s触发来强行完成故事。若能量明显不足，按实际质量/几何换同类合理触发物、选择更易触发的既有目标或调整合理接触高度，记录原因。合理的初态和参数仍无法实现时标记具体场景配置失败，不伪造结果。

## 7. 回归和交付

增加有意义的单测与真实求解smoke：两个真实盒相撞、三个真实盒传递、无触发、断链、偏心/旋转模型回放对齐。理想primitive只可作数值单测，不可作为用户成片中的真实资产。

读现有 `tests/test_scenarios.py`、`test_rolling_framework.py`、`test_asset_manager.py`，对已注册 rolling/free_fall/constant_force/damping/turntable路径做兼容检查。基线曾因本地缺 `special_coffee_cup` 和 `basketball_court` visual 出现两项失败，执行时重新分类；不能断言所有失败都来自该基线。

交付多体代码、schema样例、真实两体/三体求解结果、验证器反例报告和回归摘要。05开始前必须已证明“求解 → 全体轨迹 → 验证 → 同坐标回放”的链路。
