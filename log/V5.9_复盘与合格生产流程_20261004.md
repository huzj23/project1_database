责任在流程而不只在某个脚本：早期计划提出了“真实性、无穿模”等目标，却没有把跨软件几何同一性、源场景差异和检测器自身的失败用例落实为不可跳过的产物。对尚未打通的GPU速度作乐观排期，也推动了后续临时妥协。今后先建立这些证据，再扩展复杂度。

### 2.1 根因应分三层，不再用一个标签包办

1. **资产变换层错误：** 代理已处于厚/宽/高体坐标系；旧视觉映射使用 `C.T @ V` 后按索引与代理尺寸配对，再强制缩放。Ouija 出现约0.1538、3.9705、1.4937的逐轴缩放。问题不是“某个OBJ格式天然不行”，而是坐标系语义、轴配对和缩放链实现错了。
2. **对象变换表达错误：** 含剪切的矩阵赋给当前Blender对象后，更新得到的对象矩阵不再是原矩阵。将原始变换直接作用于顶点和读取实际对象状态必须分别测量。
3. **验证对象错误：** 检查过静态准备文件、已失真的初态矩阵、不同坐标系的AABB，或仅查悬浮不查陷入。部分检测排除了动态物体之间的关系，另一些深度单位也不是真实世界毫米。

不能把上述三层统称为“渲染格式不匹配”后只换扩展名；也不能只补第三层报警而不修前两层。

## 3. 对 V5.8 成功报告的边界修正

保留其成功事实，同时不沿用以下过强结论：

- “视觉与碰撞几何相同，所以穿模在数学上不可能发生”不成立。共同几何消除了**额外外壳错配**，但数值接触误差、漏碰、时间采样、场景碰撞缺失仍可能造成问题。已有接触记录出现过约−0.826 mm，且不是全子步全部接触点的上限证明。
- 旧 `gate_baked_geometry.py` 使用 `FTOP=max(floor_vertices.z)`。报告的 `frames:[0,63]` 是起止范围，`n_frames=64`才表示实际数量；该门禁覆盖了本次64帧，但全局高度假设**不能升级为多层桌面/坡地的通用方法**。
- 旧三角形裁剪代码只在裁剪多边形顶点取“距盒面深度”，不能仅凭单元测试名称就断言对全部角—面、边—边、共面和包含情况给出了可靠最大穿透量。长方体优先使用验证过的OBB分离轴深度，再与求解器接触及实际渲染交叉核对。
- `verify_proxy_identity.py` 的缺对象分支仍有打印后继续的路径；“缩放差为零”也不等于绝对缩放为1。正式版必须校验全部绑定、实际scale、面索引/拓扑或已证明等价的凸体表面，缺数据直接失败。
- 旧报告声称负对照已证明有效时，应提供相同检测器对具体坏输入的实际运行报告；不能把过去别的方法测得32 mm或一个曾误报的排序算法，当成所有新门禁的负对照。
- V5.8 以已改造的 `shifted/staged.blend` 为基底，只证明相对这个基底没有新增灯光，不能据此证明相对作者原始场景从未改灯光、地板、材质或可见性。
- V5.8 明确关闭了合成器。用户认可这支视频，不等于授权未来默认关闭作者的雾、合成或随意修改曝光；必须把已有例外与未来默认规范分开。
- 日志中的本地CPU改跑、线程/采样调整与历史账号使用，也不自动构成今后绕过tmux、权限边界或审批的依据。

## 4. 今后的唯一几何原则：一份定义，两端消费

### 4.1 盒子采用正式的共同资产，而不是“渲染补丁”

本阶段以用户认可的V5.8盒子为标准资产类别：共同长方体几何＋真实产品贴图＋明确的刚体假设。源扫描保留，供图案转移和尺寸依据使用；不谎称完整保留扫描凹痕或包装内装物运动。

每个资产仅生成一次规范体坐标模型，记录：

- `asset_id`、来源/许可、源文件哈希、规范网格顶点/面哈希、单位米；
- 规范化变换、原点定义、实际尺寸、质量/质心/惯性及其依据；
- 物理形状类型、实际引擎参数、collision margin、局部碰撞/惯性变换；
- 渲染网格引用、UV/材质/纹理哈希；
- 允许的简化说明与用户验收范围。

求解器和渲染器引用**同一规范几何**，不各自从高模恢复一遍轴向，不各自设置一遍尺寸。动态对象运行时只接受位置和旋转，绝对scale为1，无父级缩放、无未烘焙剪切。

“同一模型”须落到实际引擎使用的形状上：动态凹面OBJ被引擎取凸包后，哪怕文件路径一样，碰撞实体也不再与凹面显示相同。主线只使用已验证的凸长方体；未来复杂物体需另立共同凸分解/复合实体规格，不能直接把高模丢进 `GEOM_MESH` 就宣布一致。

若以后加入倒角、纸盒盖等影响轮廓的几何，必须在仿真前统一更新共同模型并重新求解。不能只在渲染端加bevel、displacement、solidify或外扩的贴花面。

### 4.2 场景中的真实支撑和障碍同样实行几何同源

桌面、桌沿、桌腿、椅子、台阶和地板等可能接触物，碰撞几何从作者场景实际evaluate后的网格提取，应用完整世界变换。保留真实边缘、缝隙与空洞；禁止用整张桌子的包围盒填满桌下空间。

静态非凸场景面可使用原三角网格构建静态碰撞；不允许为了稳定私加无限平面、平板台阶、隐藏斜坡或承托面。只提取交互范围是允许的计算优化，但边界必须在整个扫掠包络之外，且不能生成源场景没有的封口/实体。

纯远景不必全部进入求解，但须证明它不会进入动态扫掠范围。地毯、沙发、枕头、植物等没有相应软体模型的对象保留视觉原貌，路径避开；不能把需要形变的接触伪装成真实软体。

## 5. 作者场景原貌：默认零新增灯、零补丁地面

以**原始源场景**而非上一轮运行副本建立 `scene_manifest.json` 与 `scene_diff.json`。

| 类别 | 默认允许 | 默认禁止 |
|---|---|---|
| 实验物体 | 已列入任务清单的多米诺盒、唯一初始触发物 | 清单外的承托台、导轨、推动器、装饰补丁 |
| 相机 | 新建摄影机及不参与渲染/物理的相机路径辅助对象 | 摄影机穿过墙/桌，靠裁切面“切掉”遮挡物 |
| 碰撞数据 | 从原几何提取的不可见、无光照贡献的碰撞表示 | 原场景没有的物理支撑、填平桌下/台阶/孔洞 |
| 灯光 | 原作者灯、World/HDRI、原发光材质 | 新灯、头灯、跟随相机补光、发光平面；偷偷改变能量/色温/位置 |
| 原场景物体 | 保持几何、材质、摆放和原可见性 | 为开路删椅子、移家具、隐藏墙体/叶片/挡板或补地面 |
| 渲染设置 | 输出路径转到工作区，经过预览批准的采样/分辨率 | 默默关闭作者合成/体积雾、修改曝光/LUT、用新材质遮丑 |

最新用户要求比旧AGENTS中“光照不足可加Sun＋Area”的默认建议更严格；本轮**不得新增灯光**。原作者有13盏灯不等于违规，只有来源和差异能回答是否私加，不能用一个武断的灯数上限验收。

差异检查必须覆盖：对象/实例来源与变换、几何哈希、材质节点及纹理、普通灯和网格发光体、World、可见性/光线路径开关、修改器、色彩管理、合成器。仅检查对象数量不够：一个旧对象换了网格或变成发光材质也属于改动。

不适宜的区域应换原生落点或换场景，而不是修改作者环境使之适宜。确需例外，先给前后对照和理由，用户明确批准后另记版本；严禁把例外继续标成“作者原貌完全保留”。

## 6. 从资产到合格视频的标准流程

| 阶段 | 必须产出 | 放行条件 |
|---|---|---|
| G0 环境 | 版本锁定、真实开场景/纹理/单帧测试、设备与进程记录、时间估计 | 兼容环境可用，tmux/工作区/GPU约束满足；不能只跑 `--version` |
| G1 场景原貌 | 源manifest、差异清单、原作者参考图 | 新灯/补丁地板/未授权场景修改为0，资源无缺失 |
| G2 场地与摄影通道 | 实测桌面/地面区域、净空、候选首中末机位、真实效果图 | 动态扫掠和摄影通道均在合法原生空间内；用户认可场景/外观 |
| G3 几何资产 | 共同模型manifest、引擎读回、保存重开检查 | 几何、单位、原点、绝对尺度、拓扑/凸体、材质一致 |
| G4 最小物理事件 | 稳定初态、一次真实触发、关键转接实验、接触日志和对照 | 不靠关键帧移动物体；支撑与因果成立，没触发不自行倒下 |
| G5 完整物理 | 完整轨迹、所有子步接触、事件图、步长收敛和扰动试验 | 全链真实连锁，未越序/穿透/无故自启动；全部模型/参数冻结 |
| G6 运镜 | 连续相机路径、全时段可见性/净空/速度报告、低成本完整预演 | 关键接触看得清；机位不过墙、不抖、不瞬移、不靠裁切隐藏问题 |
| G7 渲染回放 | 独立打开最终replay、逐帧网格对照、最终参数测速、预演验收 | 物理与显示一致；用户批准完整低成本运镜片，而不只是首帧 |
| G8 成片 | 唯一配置渲染、MP4解码检查、关键帧、最小复现包 | 文件完整、画质及因果可辨、用户验收状态单独记录 |

原则是先花小成本发现大错误：先看原生场地、再试最困难的一次接力、再增加数量、最后优化摄影和正式采样。不能把长渲染当作诊断工具。

## 7. 合格判据：数值指标与用户视觉判断同时成立

以下为本项目下一阶段的初始工程门限，不是所有仿真通用的物理定律。阈值、单位与适用对象须在仿真前冻结，失败后不能临时放宽。

### 7.1 几何与物理

- 全部body与对象严格一一绑定，帧数与时间戳完整；任何缺失均FAIL。
- 动态共同模型保存重开后，对应世界顶点误差≤0.01 mm；同时检查面拓扑/表面、引擎形状尺寸、`scale≈(1,1,1)`和惯性局部变换。不能只看AABB或scale三个分量相互相等。
- 正式回放的全部输出帧通过同一性检查；快碰撞阶段还验证物理子步及渲染实际使用的时间样本。若启用运动模糊，必须额外验证快门区间，不能仅查整数帧。
- 盒间和盒—场景的最深穿透≤1 mm，超过则失败并输出最坏时刻、body、接触面、证据图。所有子步记录全部接触点，不能仅保存 `contacts[0]`。
- 坠落事件需要薄桌沿/地面漏碰检测与步长收敛；CCD是辅助，不能替代真实厚度、碰撞模型和子步验证。
- 支撑状态区分“桌面支撑、飞行、接收盒接触、地面支撑”。飞行不判悬浮，桌下不相对全场景最高Z判陷地。静止接触允许已实测的毫米级margin，厘米级漂浮不合格。
- 无触发控制必须保持稳定；移除关键传递物的控制中下游不启动。这里的移除仅指独立实验场景不实例化该物体，不是删除源文件。

### 7.2 场景与摄影

- 作者场景差异清单无未授权项；没有脚本新增灯、补丁地板或隐藏支撑。
- 首/中/末及跨高度关键时段均有正常背景，无建筑背面黑板、裸露地板边界、相机穿模和视野外缺口。视野扩大必须重新审查，不沿用旧机位验收。
- 以1080p为目标检查关键动作物体：高度通常≥100 px，接触处的可见短边通常≥12 px；以720p预演时按分辨率比例换算。指标不足则调整拍摄距离/布局，不能只锐化图像。
- 关键事件前后约0.15秒，施力物与受力物都应可辨认，接触区域不被第三物体遮住；单个目标的可见轮廓比例建议≥60%。这些指标是警报，最终仍需查看真实预演。
- 100%尺寸裁图检查真实纹理、接缝、图案方向和去噪闪烁。贴图非全黑/统计方差非零只证明有内容，不证明内容贴对。
- 摄影机连续移动；不为了跟住瞬间坠落而骤然俯冲，不追随盒子的每一次自转/抖动。相机动画可以设计，物体动力学不能由镜头脚本重写。

### 7.3 检测器本身也要测试

固定保存最小正反例：分离、刚好接触、0.5/2/10 mm穿入、角穿面、边穿边、完全包含、薄面高速穿越、桌下但不接触桌面、空中合法飞行、缩放错2%、原点错5 mm、遗漏一个body、缺一帧、偷偷新增发光面。

每个门禁用自己的正反例证明能正确通过和正确失败。脚本进程返回码与JSON结论同时阻断后续阶段；报告带输入哈希、脚本哈希、覆盖帧/子步和阈值。不同输入的旧PASS不能继承。
