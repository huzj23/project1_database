## 4. 学长的资产规范（`assets/README.md` 摘要）

### 4.1 命名

- ID = 目录名 = `asset.yaml` 的 `id`，小写 `<category>_<minimal_name>`，**仅 ASCII 字母数字下划线**
- 不含下载站/作者/许可证/`custom`/`final`/`new` 等过程信息
- 对象类别**固定 6 种**：`sphere` `cylinder` `cube` `cone` `food` `special`
- 环境：`kind: environment`、`category: environment`，**目录名不加 `environment_` 前缀**

### 4.2 目录结构

```
assets/objects/<asset_id>/
├── asset.yaml
├── source/                 # 未修改的原始下载
├── visual/model.glb        # 推荐的运行时对象
├── collision/              # 低面数碰撞网格 + URDF
└── license/SOURCE.md
assets/environments/<asset_id>/
├── asset.yaml
├── source/
├── visual/scene.blend      # 复杂场景用 packed Blend
├── collision/surfaces/
└── license/SOURCE.md
```

### 4.3 处理流程（9 步，关键项）

1. 原始下载**原样**放 `source/`，记录来源页/作者/许可/原始 SHA256
2. Blender 中检查单位、世界坐标、层级、材质、纹理、UV、法线、边界
3. **烘焙世界变换、移除父子层级、居中、缩放到真实米制**；烘焙负行列式（镜像）时**必须翻转法线**
   - manifest 须用 `initial_orientation.quaternion_wxyz` 记录符合常识的静止姿态（杯子底朝下；有明显长短轴的水果短轴触地）
   - **该四元数必须同时用于 Scenario、PyBullet、Blender**，不能只在预览里转 visual
4. 非 `sphere/cylinder/cube/cone` 类**必须**从归一化 visual 生成**独立低面数碰撞 mesh**；**禁止退化为包围球，禁止直接用高模 visual**
5. 环境：烘焙世界变换 → **合并为一个名为 `environment` 的 mesh** → 纹理打包；**作者灯光必须保留在 `environment_lighting` collection**，**原 World 必须保留为 `environment_world`**；**不得为简化而删除作者灯光**
6. 运行时先导入原灯光和 World，不得删改；灯光不足才显式加 `render.supplemental_lights`（先 Sun + 一盏 Area）
7. manifest 记录运行时 SHA256、实际 `size`、`scale`、碰撞与物理范围
8. 环境还需在 `configs/maps.yaml` 配置**人工核对过**的 surface；`cleanliness: verified_clear`
9. 先 AssetManager/Scenario 枚举，再固定 seed 渲染

### 4.4 碰撞约定（关键项）

- `sphere`/`cylinder`/`cube`/`cone` 用 primitive；**其他类别必须低面数 mesh**（`mesh` 或 `convex_hull`）
- 常规非基础几何**默认上限 512 三角面**；compound/静态 surface 可到 1024/2048，但**须在 manifest 记录实际值与上限**
- 动态刚体优先**封闭凸包**；凹形拆多个凸部件或 compound URDF
- **空心容器不得用单一 convex hull 封住内部**（咖啡杯用分段杯壁+独立杯底+分段把手的 compound）
- manifest 须记录碰撞 mesh 的 **SHA256、顶点/三角面数、`bounding_radius`、`support_height`**
- 带突出部件可加 `footprint_radius`（**不得大于 `bounding_radius`**）
- `support_height`/`footprint_radius` **必须按 manifest 的初始姿态计算**，不能无条件用未旋转模型的 Z 半高
- **不得把高面数渲染 mesh 交给 PyBullet**

### 4.5 用户引述的"把所有东西都设为被动项"

对应规范中：
- 环境的 `physics.mass_range: [0.0, 0.0]`（**质量 0 → 静态/被动**）
- 家具与墙体**未登记为 surface collision 的仍只是视觉几何**（即不参与仿真）
- 场景的 `static=True`（我们管线里 `static=True` → `useFixedBase=True`）

## 6. 上传/下载机制（`scripts/sync_hf_assets.py`）

### 6.1 四个命令

```bash
python scripts/sync_hf_assets.py list       # 列出将上传的资产（含大小）
python scripts/sync_hf_assets.py upload     # 上传（许可证门控）
python scripts/sync_hf_assets.py download   # 按远端 manifest 下载
python scripts/sync_hf_assets.py verify     # 校验本地与远端 SHA256
```

参数：`--repo-id`（默认 `physics-video-lab/physics-video-assets`）、`--revision main`、`--endpoint`（**默认官方站**，刻意不跟随 `HF_ENDPOINT` 镜像）、`--asset-id`（可重复）、`--allowed-license`、`--include-unknown-private`、`--dry-run`。

### 6.2 许可证门控（重要）

- **默认上传白名单只有 `CC0-1.0`**（`DEFAULT_ALLOWED_LICENSES`）
- `UNKNOWN`/`UNLICENSED`/`NONE`/空 **永远不能**进白名单（代码显式拒绝）
- `--include-unknown-private` 仅对 `list`/`upload` 有效，且**上传前会向 Hub 确认仓库确实是私有的**，否则中止

**对我们的影响**：

| 资产 | 许可 | 能否按默认上传 |
|---|---|---|
| 小熊 | **CC BY-SA 4.0** | ❌ 需 `--allowed-license "CC BY-SA 4.0"` |
| 公寓 | **CC BY-NC 4.0** | ❌ 需 `--allowed-license "CC BY-NC 4.0"` |
| 转盘 | **CC0** | ✅ 默认可传 |

两者都是**允许再分发**的许可（非 UNKNOWN），所以只要显式声明白名单即可上传到私有仓库。

### 6.3 远端 manifest

上传时生成 `cache/huggingface-assets/assets_manifest.json`，记录每个文件的**字节数与 SHA256**，并作为 `assets_manifest.json` 上传到仓库根。`verify` 据此校验。

忽略项：`.DS_Store`、`Thumbs.db`、`.part`、`.blend1/.blend2/.blend3`、`__pycache__`。

### 6.4 Git vs HF 的分工

`.gitignore` 明确：**`asset.yaml`、`license/**`、`collision/**` 进 Git**；**`visual/**`、`source/**`、纹理、`.blend` 大文件走 HF**。
