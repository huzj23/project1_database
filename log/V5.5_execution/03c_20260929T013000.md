## Two measurement errors I found and corrected

Both would have produced a **false failure**, so they are recorded rather than quietly fixed.

### 1. Hidden objects were read without their modifiers

The first comparison reported **126 triangle-count changes and 76 dimension changes**, including
`Balcony` apparently going from 300 to 20 triangles. That is the signature of a modifier not
being applied: Blender's evaluated depsgraph **skips disabled objects**, so a hidden object
evaluates to its base mesh.

`tools/v55_check_hidden_eval.py` tested this directly and confirmed it:

| reading | result |
|---|---|
| source, `hide_viewport` cleared | 0 of 126 counts changed (nothing was hidden in the source) |
| runtime, hidden | 126 of 126 matched the reduced counts |
| runtime, `hide_viewport` cleared | **126 counts changed back** |
| both sides force-evaluated | **0 mismatches** |

So the geometry was identical all along and the comparison was measuring its own blindness.
`scene_facts()` now clears `hide_viewport` on both sides, forces evaluation, then restores it —
while still recording the **saved** visibility so hiding is reported as a real difference.

### 2. The two alignment renders used different cameras

The first render pair differed by a mean of **154.8/255 across the entire frame**, with all 64
tiles changed. The cause was not the scene: the align camera was created in the source session
only and never saved into either `.blend`, so after the second `open_mainfile` the runtime
render used the runtime scene's own camera (`Cam Pouf Details`). That pair measured two
different viewpoints.

`setup_camera()` is now called per pass (idempotent by name) and `compare.json` records
`camera_identical: true`, so a camera mismatch cannot masquerade as a scene change again.

## A real defect the alignment check exposed

With the camera fixed, the frame still differed by **140.1/255 across the whole frame** with
64/64 tiles changed. That was a genuine defect in my layer build, not a measurement error: it
was archiving and **hiding** every object outside the interaction reach box — **464 objects**,
including the entire room.

03 §5 asks that the original static **display instance of a dynamic prop** be hidden and
archived so a prop cannot hit its own static copy. It does not ask for the scenery to be hidden,
and `environment_static_visual` exists precisely so scenery can be **visible but non-colliding**.
Collapsing the two produced a render of an empty void.

Corrected routing:

| category | count | layer | visible | collides |
|---|---|---|---|---|
| static collision (in reach) | 4 | `environment_static_collision` | yes | **yes** |
| soft furnishings | 4 | `environment_static_visual` | yes | no |
| backdrop / out of reach | 464 | `environment_static_visual` | **yes** | no |
| dynamic props | 4 | `interaction_dynamic_visual` | yes | via proxy |
| lights | 13 | `authored_lighting` | yes | — |
| archived static originals | 4 | — | moved, not duplicated | excluded |

Nothing is hidden and **no object is deleted**: `layer_report.json` records all 4 dynamic prop
source objects as still present, with `deleted_objects: []`, and names the reason each other
object is visible-but-non-colliding.
