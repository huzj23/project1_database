## 2. 必须纠正的一个认知：PyBullet 是可用的

**我们在 V1.2 §2.6 得出过结论：Kubric 加载 URDF 时 `useMaximalCoordinates=True`
导致求解器失效，所以物理不可用，只能走解析轨迹。**

**这个结论下得太宽了。** 学长的 `pybullet_backend.py` 用的**正是**
`from kubric.simulator import PyBullet`——同一个后端，而且跑出了真实动力学。

他绕过的两个关键点（代码里都有注释）：

| 坑 | 他的解法 |
|---|---|
| URDF 加载后 setter 未注册 | **先 `scene += obj` 链接到 PyBullet，再设置** `position/quaternion/velocity/mass/friction/restitution` |
| Kubric 未暴露惯量设置 | 直接调 `simulator._physics_client.changeDynamics(body_id, -1, mass=..., localInertiaDiagonal=..., ...)` |

另外：**球体类物体他不走 URDF**，直接用 `kb.Sphere(...)` 原生体
（`collision.type: sphere` → PyBullet 原生球），完全绕开 URDF 加载器。

**结论**：我们要做的不是"自建物理"，而是**采用他的适配层**。

## 3. 防穿模的真正答案

学长的方案是三层，比我原计划的"逐帧校验器"更彻底：

### 第一层：让求解器解算接触（根本）

物体不是被"放到"某个位置，而是**被重力/力/摩擦推着走**，接触由 Bullet 解算。
**穿透在物理上是被排斥力阻止的**，不是靠事后修补。

### 第二层：渲染前显式校验（`validation/__init__.py`）

| 校验项 | 阈值/含义 |
|---|---|
| `initial_surface_penetration` | 初始底面不得低于支撑面 **5 mm** 以上 |
| **`max_surface_penetration`** | **过程中最大穿透 > 4 cm 直接判废** |
| `require_expected_collision` | 必须有**真实接触事件**（`collisions.json` 非空） |
| `require_bounce` | 落地后必须有**向上速度**（≥ 0.05 m/s） |
| `supported_fraction` | ≥ 90% 的帧物体必须**在支撑面上**（±3 cm） |
| `require_in_map_bounds` | 不得越出合法区域 |
| `trajectory_extent_object_ratio` | 轨迹/物体尺寸比 ≤ 18（防止物体太小） |

### 第三层：**丢弃而不是修补**

> "Reject invalid samples instead of repairing their trajectories."

他的批次是**采样 → 校验 → 只渲染通过的**，不通过的换种子重采。
这从根本上避免了"渲染完 36 条才发现 12 条穿模"。

**这就是他评审我们"穿模"时没说出口的那半句：不是模型没调好，是流程没有闸门。**

## 5. 七种运动在他的框架里的映射

他的框架扩展方式（`PIPELINE.md` §10）：**加一个 yaml + 一个 scenario py + 一个 validator，
复用其余全部**。

| # | 运动 | 状态 | 实现方式 |
|---|---|---|---|
| 1 | **匀速（滚动/平动）** | ✅ 他已有 `rolling` | 直接复用 |
| 2 | **匀加速** | ✅ 他已有 `constant_force` | 直接复用（恒定外力 `F=ma`） |
| 3 | **自由落体** | ✅ 他已有 `free_fall` | 直接复用（真实接触 + 反弹） |
| 4 | **抛体** | ➕ 新增 | `velocity=(v₀cosθ, 0, v₀sinθ)` + 重力；PyBullet 积分出抛物线，落地自然反弹 |
| 5 | **圆周（转盘带动）** | ➕ 新增 | **转盘设为 kinematic 刚体**绕 Z 恒速旋转，物体靠**摩擦被带动**——这是真物理，不是我原来打算的"轨迹画圆" |
| 6 | **转盘自转** | ➕ 新增 | 同上，物体放在转盘中心附近，随盘自转 |
| 7 | **阻尼** | ➕ 新增 | PyBullet 的 `linearDamping` / `angularDamping`，物体减速停下 |

**关键**：#5 和 #6 用**运动学转盘 + 摩擦耦合**，一次性解决了
"圆周凭空诡异"（有物理解释）和"绕水平轴穿模"（物体坐在盘面上，不穿地）。

**每种运动的 validator**：
- 抛体：验证抛物线拟合残差、射程、无穿透
- 圆周：验证物体始终在盘面内、轨道半径稳定、角速度与盘匹配
- 转盘自转：验证物体随盘旋转、不打滑脱落
- 阻尼：验证速度单调递减、末速度趋近 0

## 6. 场景与素材

### 6.1 场景 —— 学长已有 3 个，正好是"日常"的

| 环境 | 对应学长的诉求 | 规模 |
|---|---|---|
| `basketball_court` | **运动场馆** | 969 个网格、135 万顶点、124 材质、保留 6 盏作者灯光 |

我们不需要再去 Poly Haven 找 HDRI 贴图。而且这些是**真三维场景**，有视差和遮挡，
比 HDRI 背景真实得多。

### 6.2 物体 —— 他已有 8 个

| 类别 | 物体 | 碰撞方式 |
|---|---|---|
| 球类（4） | `sphere_basketball` / `football` / `baseball` / `volleyball` | **PyBullet 原生球** |
| 食物（3） | `food_apple` / `food_lime` / `food_lychee` | 低模网格 URDF |
| 容器（1） | `special_coffee_cup` | **复合凸体**（中空，不能用实心凸包） |

**回答你"可以接受没有球"**：其实**学长已经把球补齐了**（4 种球）。
所以我们不必纠结 GSO 有没有球——直接用他的球类资产，GSO 物体作为**增量**接进来。

### 6.3 GSO 物体的接入（我们的增量）

按他的 `asset.yaml` 规范，每个 GSO 物体需要：

```
assets/objects/<category>_<name>/
├── source/                 # 原始下载（GSO 的 obj + texture.png）
├── visual/model.glb        # 归一化后的运行时视觉
├── collision/model.obj     # 低模碰撞网格（GSO 自带的 collision_geometry.obj ✅）
├── collision/model.urdf
├── asset.yaml              # 含 initial_orientation / support_height / footprint_radius
└── license/SOURCE.md       # CC BY-SA 4.0 署名
```

**好消息**：GSO 每个物体**自带 `collision_geometry.obj`**（我们之前没用上），
直接可用作碰撞网格。

## 8. 实施计划

### 阶段 0 —— 环境搭建（不依赖缺失资产）
1. 建立 `physics-video-sim` 的 conda 环境（他要求 `python -m pip install -e ".[dev]"`）

3. 跑 `pytest` 与 `scripts/check_blender.py` 确认骨架可用
4. **用他的碰撞代理 + 我们自己的球模型跑通一条 `free_fall`**，验证 PyBullet 真积分在我们服务器上可行

### 阶段 1 —— 补齐 4 种新运动
按 §5 逐个加 `configs/scenarios/<name>.yaml` + `src/physim/scenarios/<name>.py` + validator。
**优先做 `free_fall` 与 `projectile`**——学长最关心的"落地会不会像铁块"由它们回答。

### 阶段 3 —— 7 种运动 × 2–3 素材
