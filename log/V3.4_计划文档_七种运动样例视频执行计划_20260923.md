## 0. 前置结论（本计划的三块基石）

### 0.1 ✅ 求解方法审查：**确认是严肃的微分积分求解**

用户要求审视"是否主要使用学长的微分积分严肃求解方法"。**审查结论：是。**

| 证据 | 位置 |
|---|---|
| 真实步进 `stepSimulation()` | `kubric/simulator/pybullet.py:475` |
| 每视频帧 **15 次物理子步**（240 Hz / 16 fps） | `pybullet.py:376` |
| 轨迹 = 引擎读数（`getBasePositionAndOrientation` / `getBaseVelocity`） | `pybullet.py:429-435` |
| 适配器**零后处理**（仅 float 转换 + 时间戳） | `physics/pybullet_backend.py:170-182` |
| scenario **只设初值**，不写逐帧位置 | `scenarios/{free_fall,rolling,constant_force}.py` |
| 接触/摩擦/恢复系数**进求解器** | `pybullet_backend.py:139-148` |
| Blender **只回放关键帧**，无第二求解器 | `render/blender_backend.py:357-361` |

**全仓库 grep 无** `0.5*g*t^2`、`g*t`、`v0*t`、`math.sin(t)` 形式的逐帧位置赋值。
唯一用到解析公式处（`constant_force.py:63,82-85`）只用于**反推力大小**与**出生点范围**，
**不写进 trajectory**。

> **唯一风险点**：`pybullet.py:654-671` 存在未使用的 `add_persistent_velocity`，
> 它会逐子步重置速度。**当前无任何引用**。本轮新运动**禁止启用它**。

### 0.2 ✅ 资产边界：**只用我们自己的资产**

| 类别 | 我们的资产 | 状态 |
|---|---|---|
| **场景** | ReplicaCAD 我们的下载：5 stages + **91 布局** + 92 prop + 7 光照配置 | ✅ |
| **物体** | **6 个 GSO 真实扫描物体** + 我们生成的**红木转盘** | ✅ |

> **明确排除**：学长的 `basketball_court` / `classroom` / `street` 场景，
> 以及 `sphere_*` / `food_*` / `special_coffee_cup` 物体。
> 理由：**这些视觉资产根本不在磁盘上**（V3.3 §6），且学长自己会用。
> 我们的任务是用**自己的资产**跑真实仿真。

### 0.3 ⚠️ 必须更正的前述错误

V3.3 §9 已记录：我此前汇报"物体落在场景自带的 94.29 m² 真实地板上"
**不准确**。求解器**不读** `asset.yaml` 的 `collision`，只读 `maps.yaml` 的 region，
实际支撑面是 **2.89 m²**。渲染正确是因为该 region 本就位于地板之上。

### 1.1 关于 #4 抛体的重要发现

**`free_fall.py:52-58` 已经支持水平初速**：

```python
horizontal_speed = uniform(rng, physics.get("horizontal_speed_range", (0.0, 0.0)))
linear_velocity = (direction[0]*horizontal_speed, direction[1]*horizontal_speed, vertical_speed)
```

且 `surface_sampler.sample_position(..., travel_distance=horizontal_speed*duration, ...)`
已预留落点空间。**抛体只需新建一份 yaml（填非零 `horizontal_speed_range`），
无需新 scenario 代码。** 这是成本最低的一条。

## 2. 三种实现层次（Tier）

按**改动量**分层，便于用户决定今晚推进到哪一层。

### T1 —— 零代码改动（现有 scenario 直接跑）

| 运动 | scenario | 所需 |
|---|---|---|
| #1 匀速 | `rolling` | 新建 `rolling_gso.yaml` |
| #2 匀加速 | `constant_force` | 新建 `constant_force_gso.yaml` |
| #3 自由落体 | `free_fall` | ✅ `free_fall_gso.yaml` **已跑通** |

**产出 9 条。改动 = 2 份 yaml。**

### T2 —— 小改动（加一个字段 / 一份 yaml）

| 运动 | 所需改动 |
|---|---|
| #4 抛体 | 只加 yaml（`horizontal_speed_range` 非零）。**已验证代码支持** |
| #7 阻尼 | ① `asset.yaml` 加 `damping_range`；② `AssetSpec` 加载该字段；③ 新增 `damping.py` scenario；④ `pybullet_backend` 把 `linearDamping`/`angularDamping` 传给 `changeDynamics`；⑤ 新增 `validate_damping` |

**产出 5 条。阻尼的新增代码量约 80–120 行**（复用 `common.py` 与现有 validator 骨架）。

### T3 —— 真实架构扩展（转盘 #5/#6）

**为什么这是最难的一层**：物理后端**只创建一个动力学体**：

```python
# pybullet_backend.py:78-107  —— 全文只有这两种分支
simulated_object = kb.Sphere(...)          # 或
simulated_object = kb.FileBasedObject(...)
scene += [support_body, simulated_object]
```

`simulate()` 返回**单条** trajectory（`object_animation = animation[simulated_object]`），
渲染后端也只回放**一个**对象的关键帧。转盘需要：

| 需求 | 缺口 |
|---|---|
| 第二个动力学体（盘） | 后端只建一个 |
| 盘的位置钉住 + 角速度驱动 | 无此机制（`add_persistent_velocity` 存在但**禁止使用**） |
| 两体轨迹都要回放 | `SimulationResult` 只有一条 trajectory |
| 盘的视觉（红木材质） | 渲染后端只对 `simulated_object` 应用材质 |

**改动量估计 250–400 行**，涉及 `ScenarioSample`、`SimulationResult`、
`pybullet_backend`、`blender_backend` 四个文件的接口扩展。

> **好消息**：`tools/tt_replay.sh` 已有**完整可用的转盘 + 关键帧转录范例**
> （V3.2 §2.3 的四步驱动、6 条陷阱、关键帧铁律全部实测过）。
> 因此**物理机制是已知的**，工作在于**把它接进 pipeline 的架构**。

## 3. 支撑面方案（含 §0.3 的更正）

### 3.1 现状

| 面 | 来源 | 面积 |
|---|---|---|
| `floor` | `maps.yaml` region `bounds_xy = [0.15,1.85,-5.15,-3.45]` | **2.89 m²** |

### 3.2 建议

| 运动 | 方案 |
|---|---|
| #1–#4、#7（floor） | **先用现有 2.89 m² region**——它已验证清晰、取景可复现。**不改**。 |
| #5/#6（转盘） | **新增一个 `table_top` region**，用实测桌面参数（z=0.7584，中心 (0.414, 0.175)，跨度 1.399×0.852 m） |

### 3.3 关于"用整个 94.28 m² 地板"

**建议不在今晚做**。理由：

1. 它**不是**七种运动的阻塞项（2.89 m² 足够跑通全部运动）
2. 正确做法（V3.3 §9.4 路径 A：提取地板 slab 的 mesh 碰撞）是**独立的一项工作**
3. 扩大 region 的 `bounds_xy`（路径 B）会让 box **覆盖到家具**，可能引入穿模

**若要彻底解决**，建议**作为独立任务**在样品跑通后处理。

## 4. 验收标准（每条视频）

### 4.1 通用（V3.0 §4 承袭 + 本次实测补充）

| 项 | 标准 | 当前状态 |
|---|---|---|
| 物理校验 | `validation.valid == True`，`reasons == []` | ✅ 基准测试通过 |
| 穿模 | `max_surface_penetration == 0` | ✅ 实测 0.0 |
| **运动帧占比** | **≥ 50%** | ✅ 实测 **66.7%** |
| 视频真实运动 | 每帧 md5 互不相同 | ✅ 实测 **16/16** |
| 分辨率 | 1920×1080 | ✅ |
| 产物 | rgb/depth/seg + video.mp4 + trajectory.json + collisions.json + metadata.json | ⚠️ **seg 全黑（见 §5.1）** |
| 关键帧转录 | 相邻帧像素差 > 500 | ✅ 实测 11/15 帧 |

### 4.2 各运动专属（V2.0 §5 承袭，本次补默认值）

| 运动 | 判据 | 默认阈值（本次拟定） |
|---|---|---|
| #1 匀速 | 速度相对变化小 | `max_speed_relative_change ≤ 0.15`（既有） |
| #2 匀加速 | 加速度均匀 | `max_acceleration_relative_std ≤ 0.50`（既有） |
| #3 自由落体 | 真实接触 + 反弹 | `require_bounce ≥ 0.05 m/s`；**soft 物体走 `validate_free_fall_soft`（不要求反弹）** |
| #4 抛体 | 抛物线拟合残差 / 射程 / 无穿透 | 新增：R² ≥ 0.95，`min_range_object_extent_ratio ≥ 2.0` |
| #5 圆周 | 轨道半径稳定 | 新增：`radius_std/radius_mean ≤ 0.05`，需 ≥ 1.5 圈 |
| #6 转盘自转 | 随盘旋转不打滑 | 新增：角速度与盘匹配，`slip_ratio ≤ 0.15` |
| #7 阻尼 | 速度单调递减 | 新增：末速 ≤ 初速 10%，衰减拟合 R² ≥ 0.9 |

> ⚠️ **注意**：`supported_fraction ≥ 0.9` 的门槛**只对 rolling / constant_force 生效**
> （`validation/__init__.py:109,138`），`free_fall` 有自己的判据。
> 基准测试 `supported_fraction = 0.6875` 仍 `valid=True`，与此一致。

## 8. 本计划不做什么（明确边界）
