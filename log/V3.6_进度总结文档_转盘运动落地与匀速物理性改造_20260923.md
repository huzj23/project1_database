## 1. 匀速运动的物理性问题（用户批评成立）

### 1.1 用户的批评是对的

"管子怎么能无缘无故地在地面上匀速运动呢" —— 这是一个**物理动机**问题，不是观感问题。一个凸形容器在水平地面上做长时间匀速直线运动，需要解释（谁推的？为什么没有摩擦减速？），而原配置用的正是 `friction_range: [0.0, 0.0]`（把摩擦设为零来换取"能滑起来"），这在物理上是**为了通过校验而人为取消摩擦**，是伪装的预定义轨迹。

### 1.2 实测：我们手上的物体没有一个能滚

对每个资产的碰撞网格测量截面圆度 `r_cv`（越接近 0 越圆）与滚动摆动 `roll_wobble`：

| 资产 | 尺寸 (m) | r_cv | roll_wobble (m) | 能滚? |
|---|---|---|---|---|
| **`gso_whey_protein_vanilla`** | 0.124×0.124×0.170 | **0.0783** | **0.0048** | ✅ **唯一** |
| `gso_mad_gab_refresh_card_game` | 0.158×0.158×0.158 | 0.2044 | 0.0323 | ❌ |
| `gso_ecoforms_plant_container_gp16a` | 0.166×0.166×0.162 | 0.2587 | 0.0391 | ❌ |
| `gso_down_to_earth_orchid_pot` | 0.141×0.140×0.128 | 0.2767 | 0.0312 | ❌ |
| `gso_room_essentials_fabric_cube` | 0.283×0.287×0.286 | 0.2882 | 0.0886 | ❌ |
| `gso_sootheze_cold_therapy_elephant` | 0.269×0.222×0.210 | 0.3272 | 0.0550 | ❌ |

**结论**：除 whey 管外，其余全是方盒/花盆/玩偶，**没有一个能滚**。所以"把摩擦设为零让它滑"曾经是唯一的出路 —— 但这是错的。

### 1.3 正确修法：把 whey 管横放，让它真正滚起来

横放后长轴水平，滚动截面半径 0.06097 m（直立 `support_height` 是 0.08232 —— **必须换成截面半径**，否则生成高度错、且 `supported_fraction` 会失败）。

### 1.4 实测验证：确实是滚动而非滑动

判据是**无滑滚动条件** `slip = |ω|·r / |v|`，1.0 = 纯滚动，≈0 = 纯滑动：

| 量 | 实测 | 判定 |
|---|---|---|
| `initial_quaternion` | (−0.0139, −0.0139, **0.707, 0.707**) | 绕水平轴 90°，**确实横放** |
| `support_height` | **0.06097**（直立为 0.08232） | 用的是**截面半径** |
| z 范围 | 0.06167 ~ 0.06378（跨度仅 2.1 mm） | **贴地平稳，无翻滚** |
| \|v\| | 0.1238 ~ 0.1568 m/s | 匀速 |
| \|ω\| | 1.9951 ~ 2.5537 rad/s | 持续转动 |
| ω 方向（帧0） | (−0.087, **2.215**, 0.0) | **自转轴水平** |
| **slip = \|ω\|·r/\|v\|** | **0.9731 ~ 1.0089** | **≈1.0：无滑滚动** |
| `valid` | True，`reasons=[]` | 通过 |

> **物理意义**：管子横放在地上滚动时，匀速运动**不需要任何解释** —— 牛顿第一定律，理想滚动无滚动阻力。这比"用力推一个箱子让它匀速滑"诚实得多。用户要的正是这个。

## 2. 相机：新增 `fixed` 策略（为满足"使用已通过的机位"）

### 2.1 为什么必须新增

原 `trajectory_side` 策略**从每条片子自己的运动反推机位**（`side` 决定在轨迹哪一侧，`azimuth_offset_degrees` 由种子随机）。它**在结构上无法复现**一个已经审查通过的绝对位姿：
- 物体/种子一变，机位就变；
- 无法保证"和上次通过的那张图完全一样"。

而用户明确要求"使用**我之前通过的**相机位姿"，这是一个**回归复现**需求，必须支持绝对位姿。

### 2.2 实现

`src/physim/camera/__init__.py` 新增 `fixed_camera(result, config)`，`pipeline.py` 的 `_camera_config` 接受 `policy: fixed` 并**跳过一切推导与随机**（不注入 `azimuth_offset_degrees`、不做 `side` 翻转）。配置形态：

```yaml
camera:
  policy: fixed
  position: [x, y, z]
  look_at: [x, y, z]
  focal_length_mm: 50.0
  framing:
    sensor_width_mm: 36.0
```

### 2.3 已验证

| 检查 | 结果 |
|---|---|
| 位姿逐字使用 | `position (0.934, -0.485, 1.1784)` / `look_at (0.414, 0.175, 0.8084)` / 50 mm |
| **与轨迹无关** | 传入两组相反的假轨迹，输出位姿**完全相同** → True |
| 不注入随机 | `azimuth_offset_degrees` 未出现 → True |
| 退化位姿防护 | position==look_at → 抛 `ValueError` ✅ |
| 非 3 向量防护 | 2 向量 → 抛 `ValueError` ✅ |
| 缺键防护 | 缺 position/look_at → 抛 `ValueError` ✅ |
| **向后兼容** | 原有 14 条片段预检**仍 14/14 PASS** ✅ |


### 3.2 关键物理发现：圆弧角度只由 ω 决定

`arc = ω × t`，**与轨道半径无关**。这条被实测证实：把轨道半径从 0.35 → 0.55 扫一遍，**arc 恒为 131.6°**：

| 轨道带 | 轨道半径实测 | 弧角 | 结论 |
|---|---|---|---|
| 0.35–0.50 | 0.131–0.133 | 131.6° | 半径变了 |
| 0.42–0.50 | 0.140–0.142 | 131.6° | **弧角不变** |
| 0.45–0.52 | 0.147–0.150 | 131.6° | **弧角不变** |
| 0.48–0.55 | 0.156–0.159 | 131.6° | **弧角不变** |
| 0.50–0.55 | 0.159–0.161 | 131.6° | **弧角不变** |

**131.6° 只有三分之一圈，根本不像"环形转动"。** 跑满一圈需 `ω = 2π/5.0625 = 1.241 rad/s`。
