## 0. 结论摘要（先读这一节）

本次比对得到三个必须立刻知道的结论：

1. **改动量远小于预期，且高度集中。** 上游 162 个文件，我们的副本 168 个文件。相对上游只有 **6 个新增、0 个删除、11 个修改**，其余 **151 个文件与上游逐字节相同**。全部改动集中在 `src/physim/**`（12 个文件）和 `configs/**`（5 个文件）。

2. **`assets/`、`docs/`、`scripts/`、`tests/`、根目录文件与上游完全一致。** 也就是说"我们用自备 GSO 资产 + 自建 ReplicaCAD 地图替换了上游示例资产/地图"这件事**没有体现在这份工作副本里**。`configs/maps.yaml`、`configs/assets.yaml`、`configs/local.yaml`、`configs/server.yaml` 也全部与上游逐字节相同，其中只声明了上游自带的 `basketball_court` / `classroom` / `street` 和 8 个 `food_*` / `sphere_*` 物体。

3. **但配置里引用了这份副本中并不存在的资产与地图。** `rolling_gso.yaml` / `turntable_*_gso.yaml` 引用了 `replicad_apartment`、`turntable`、`gso_*` 等 id，而本地既没有对应目录、也没有在注册表里声明。这些文件在 **服务器** 上，本地副本是不完整的。

另外，核实"已知上下文"时发现 **3 处与描述不符**，以及 **1 处硬缺陷**，详见 §5 与 §6。其中最重要的一条：

> **`configs/scenarios/rolling_gso.yaml` 写了 `physics_fps: 560`，但 `physics/pybullet_backend.py` 里那条 `if sample.physics_fps != 240: raise ValueError(...)` 硬门控原封不动，且全仓库不存在任何 `setTimeStep` 调用（只在一句注释里出现过）。因此 560 Hz 这条路径在当前代码下必然抛异常，不可能跑通。**

## 4. 逐项功能改动说明

### 4.1 `src/physim/scenarios/turntable.py`（新增，最大单笔改动）

**改了什么**：新增 `TurntableScenario` 类，同时服务 `turntable_carry`（运动 #5 圆周运动）与
`turntable_spin`（运动 #6 转盘自转）两个 scenario 名。它负责：解析第二个体（转盘 disc）的
`AssetSpec`、选定桌面 region、决定 disc 落点与角速度、决定 actor 在盘面上的轨道半径与起始角、
并把这一整套参数写进 `ScenarioSample` 的 `support_*` 字段。

**为什么**：需要一个"物体被旋转盘面带着走"的运动。关键在于**不能把圆弧写进轨迹** ——
所以 sampler 只决定初始条件与驱动量（盘的角速度、盘的位置、actor 的落点），
actor 的圆周路径完全由 disc↔actor 的接触摩擦在求解器里产生。

**效果**：
- actor 初始线速度与角速度都被**显式置零**（`linear_velocity=(0,0,0)`、`angular_velocity=(0,0,0)`），
  圆弧不可能是"预置速度"的结果；
- 盘面放不下 actor 时报 `ValueError`（`orbit_radius + asset.radius > disc_radius`）；
- `_support_asset()` 要求必须传入 `AssetManager`，否则抛错 —— 即 scenario 不自己拼路径，
  符合项目"scenario 不构造绝对路径"的约束。

### 4.2 `src/physim/scenarios/__init__.py`（修改）

**改了什么**：
1. `ScenarioSample` 新增 2 组字段：
   - `linear_damping` / `angular_damping`（默认 0.0）；
   - 驱动支撑体 16 个 `support_*` 字段 + `orbit_radius` + `actor_support_z`，全部有安全默认值。
2. `create_scenario(config, asset_manager=None)` 新增可选参数；注册 `turntable_carry` /
   `turntable_spin` → `TurntableScenario`，并注册 `damping` → `DampingScenario`。

**为什么**：让"第二个动态体"和"阻尼"成为 sampler 与 solver 之间的正式契约字段，
而不是散落的魔法值。默认值的设计意图是**向后兼容**：不声明即等于上游行为。

**效果**：单物体 scenario 的 sample 与上游逐字段一致（默认值不改变任何既有路径）。
**但 `damping` 分支是坏的**，见 §6.1。

### 4.3 `src/physim/scenarios/common.py`（修改，+280 行）

**改了什么**：
1. `base_physics()` 新增可选 `physics` 覆盖参数：`mass_range` / `friction_range` /
   `restitution_range` 可由 scenario config 的 `physics` 块覆盖。
2. 新增 **per-scenario 初始姿态**机制（`orientation` 块）：
   `orientation_entry` / `side_orientation_requested` / `side_pose` /
   `resolve_initial_orientation` / `collision_hull_vertices` /
   `side_collision_geometry` / `matrix_to_quaternion_wxyz`，以及常量
   `ORIENTATION_UPRIGHT` / `ORIENTATION_SIDE`。
3. `side_pose()` 把物体长轴放倒、垂直于行进方向，并**从旋转后的碰撞网格重新测量**
   `support_height` 与 `footprint_radius`。

**为什么**：用户的物理性质疑 —— 一个直立容器在水平地面上长时间匀速平移没有物理动机。
把同一个容器**横放**，它就真的**滚**起来，而理想无滑滚动下的匀速正是牛顿第一定律。
`side_pose` 里"重新测量支撑高度"是必需的：继续用 manifest 里直立的 `support_height`
会把物体生成到地板以下 2 cm，直接让 `supported_fraction` 崩掉。

**效果**：
- 该机制**完全 opt-in**：config 里没有 `orientation` 块、或 policy 不是 `side`、或 asset 不在
  `asset_ids` 列表里时，返回的位姿/高度/半径与 manifest 完全相同 → 既有样本 bit-identical；
- 长轴不在 Z 轴的资产会明确报错，而不是悄悄算错；
- 支持 `refined_collision` 走资产可选的 `side_collision` 精细碰撞体（注释记录：64 顶点粗凸包
  把光滑罐体近似成约 16 边形，会 facet-to-facet 摇摆并停下，衰减 +0.674 /s；精细凸包为 -0.055 /s）。

### 4.4 `src/physim/scenarios/rolling.py`（修改）

**改了什么**：`RollingScenario.sample()` 在算速度与落点**之前**先调用
`resolve_initial_orientation()` 取得 `(initial_quaternion, support_height, footprint_radius, orientation)`，
随后：
- `angular_velocity = cross(normal, linear_velocity) / support_height`（原本用 `asset.support_height`）；
- `sample_position(radius=footprint_radius, support_height=support_height, ...)`；
- `ScenarioSample(..., radius=footprint_radius, support_height=support_height, initial_quaternion=initial_quaternion, ...)`；
- 新增静态方法 `_contact_physics()`，允许 `orientation.friction_range` 覆盖接触摩擦范围。

**为什么**：横放后滚动截面半径 ≠ 直立支撑高度，用错值会让生成高度错、无滑条件也错。
摩擦必须能"咬住"接触点才谈得上滚动，所以滚动资产需要自己的摩擦带（`[0.30, 0.60]`），
而**不能**改共享的 `physics.friction_range`（那是给"滑动"资产用的 `[0.0, 0.0]`，
一改就会刹停 `selection` 里其他所有资产）。

**效果**：`rolling_gso.yaml` 中只有 `gso_whey_protein_vanilla` 走横放 + 有摩擦的滚动路径，
同 config 里的 fabric cube 仍用 manifest 直立位姿与零摩擦。**但本文件的调用点当前会崩，见 §6.2。**

### 4.5 `src/physim/physics/pybullet_backend.py`（修改，+258 行，核心）

**改了什么**：
1. 新增 `_body_states()` 辅助函数（把逐帧数组打包成 `BodyState` 元组）。
2. `changeDynamics` 增加 `linearDamping` / `angularDamping`（`getattr(sample, ..., 0.0)` 取默认 0）。
3. `simulate()` 分叉：`sample.support_asset_id is not None` 时走 `_drive_support()`，
   否则走上游原有的 `simulator.run()` 单物体路径。
4. 新增 `_drive_support()`：**四步驱动循环**，逐物理子步
   (1) 只钉住 disc 的**位置**、原样回读并回写**姿态**（绝不重置为单位四元数）；
   (2) `resetBaseVelocity(disc_id, [0,0,0], angular_velocity)` 重新施加恒定角速度（"电机"）；
   (3) `stepSimulation()`；(4) 每视频帧重复 `physics_fps // video_fps`（=15）次；
   每视频帧记录 actor 与 disc 各一组状态。
5. 新增 `_disc_contact()`：读取 disc↔actor 接触点，记录**法向力**与**切向摩擦力**
   （`lateralFriction1/2` 的模与方向）。
6. collisions 序列化时透传 `friction_force` / `friction_direction`，
   并同时接受 str 与带 `.name` 的 instance 两种形态。

**为什么**（代码注释里逐条记录了已经踩过的坑）：
- `static=True` 会让 URDF loader 设 `useFixedBase=True`，把盘**焊死**、永不转动；
- `changeDynamics(mass=0)` 同理；
- 每子步把姿态重置为单位四元数会**抹掉**刚积分出来的旋转；
- 每子步"瞬移"位姿而不让求解器解接触，实测 slip 恰好 0.00 —— 盘看起来在转，其实什么都没耦合；
- 每视频帧只 step 一次（而非 15 子步）会让运动看起来慢约 10 倍；
- **模块级 `pybullet` 函数打的是 physics client 0**：Kubric 每个 `PyBullet` 实例自开 client，
  只有进程里**第一个** simulator 拿到 id 0。多样本运行时第二个 simulator 会在过期 client 上
  step，世界永不前进，表现为"盘没转"。因此全部 step 与状态读取都走
  `simulator._physics_client`（该 proxy 每次调用都绑定 `physicsClientId`）。

**效果**：actor 的圆周运动是 disc↔actor 接触摩擦的**结果**，法向力只负责托住它、
切向摩擦才是把它扫过圆弧的力 —— 两者都被记录进 `collisions.json`，使"被带走"成为**可测主张**。
`friction` 被 clamp 到 ≤1.0（Kubric 的 trait 限制，非 PyBullet 限制）并打印 `DIAG` 记录，
不静默吞掉。

### 4.6 `src/physim/physics/__init__.py`（修改）

**改了什么**：`SimulationResult` 新增 `support_trajectory: tuple[BodyState, ...] = ()`

**为什么**：让"第二个体"的轨迹成为一等公民，可被 validator 与 renderer 消费。

### 4.7 `src/physim/render/blender_backend.py`（修改）

**改了什么**：
1. `BuiltBlenderScene` 新增 `support_object: Any = None`。
2. 新增 `purge_stale_frames()`：在 `build_scene()` 开头清理 scratch 目录里遗留的
   `frame_*` / `rgba_*` / `depth_*` / `segmentation_*` 的 `.exr`/`.png`。
3. `build_scene()` 在 `simulation.support_trajectory` 非空且 `sample.support_visual_path` 存在时，
   额外建一个 `kb.FileBasedObject(name="support_object", ...)`，`segmentation_id=3`，
   并用 `render_import_kwargs={"axis_forward":"Y","axis_up":"Z"}` 导入。
4. 关键帧回放新增 disc 分支：按 `simulation.support_trajectory` 逐帧

### 4.10 `src/physim/validation/__init__.py`（修改，+393 行，第二大改动）

**改了什么**：
1. 新增 `_expected_support_z()`：期望支撑高度可由 `sample.actor_support_z` 声明，
   缺省回退到 map surface 的 z（既有行为）。
2. `_measure()` 的 `expected_z` 改用它。
3. 新增 4 个 validator：
   - `validate_free_fall_soft()` —— 软物体落地：要求**真的撞上**、穿透可忽略、留在支撑面上、
     末段**静止**（`did_not_settle`），并**限制回弹上限**（`max_soft_rebound_speed`）；
   - `validate_damping()` —— 阻尼：速度须**单调衰减**、末速/初速比须落在
     `[min_decay_ratio, max_decay_ratio]` 之间（既不"没衰减"也不"直接刹死"），
     并与解析解 `exp(-k·t)` 对比（`damping_decay_mismatch`）；
   - `validate_turntable_carry()` / `validate_turntable_spin()` —— 共用 `_turntable_geometry()`。
4. `_turntable_geometry()` 新增一组**可测量量**：`net_arc_degrees`（解缠后的净扫角，
   可超 360°）、`net_radial_displacement`、`max_radius`/`mean_radius`、
   `radial_fraction_of_travel`、`disc_rotation_degrees`（从盘的四元数实测）、
   `slip_ratio`（|actor 弧角| / |盘转角|，1.0 = 完全被带走，0.0 = 盘在底下空转）。
5. 新增 `_yaw_degrees()`：从旋转矩阵逐帧读 yaw、相邻差 wrap 到 (-π, π] 后累加，

**为什么**：每条新运动的**物理内容**都需要对应的判据，而不是"看起来对"。
特别是 `slip_ratio` 与 `disc_rotation_degrees`：前者证明 actor 是被摩擦带走的
（而不是盘在底下空转），后者证明盘**真的转了**（而不是只相信命令的 omega）。

**效果**：`turntable_carry` 要求最小弧角（默认 60°，config 提到 120°）、径向位移小、
径向占比低、slip 足够高、盘确实转过；`turntable_spin` 则要求盘转过最小角度、
actor 共转且**不向外漂**（`max_radial_growth`）。

## 6. 核实过程中发现的缺陷与不一致（重要）

以下每一条都有**实际执行的命令与真实输出**作为依据，不是静态推测。

### 6.1 `damping` scenario 是半落地状态 —— 一调用就 `ModuleNotFoundError`

`create_scenario()` 里有：

```python
if scenario_name == "damping":
    from physim.scenarios.damping import DampingScenario
    return DampingScenario(config)
```

但 `src/physim/scenarios/damping.py` **不存在**。实测（`verify_claims.py`）：

```text
modules present: ['common', 'constant_force', 'free_fall', 'rolling', 'turntable']
  [MISSING] DampingScenario -> physim.scenarios.damping  (file damping.py exists=False)
```

同时 `configs/scenarios/damping_gso.yaml` 也不存在。因此：
- `create_scenario({... 'scenario': 'damping'})` → `ModuleNotFoundError`；
- `validate_damping()` 与 `linear_damping`/`angular_damping` 字段虽然齐备，但**没有任何 scenario 会设置它们**；
- 阻尼运动的授权版配置只存在于 `tools/cfg_damping_gso.yaml`，未同步进工作副本。

### 6.2 `rolling` 调用点传入不存在的字段 —— 必然 `TypeError`

`scenarios/rolling.py` 的 `ScenarioSample(...)` 调用点（第 98 行，**无条件执行**）传了
`orientation=` 与 `collision_simulation_path=` 两个关键字：

```python
initial_quaternion=initial_quaternion,
orientation=orientation,
collision_simulation_path=orientation.get("collision_simulation"),
```

而 `ScenarioSample` 的 40 个字段里**没有**这两个名字。实测（`verify_runtime.py`）：

```text
-- baseline kwargs only (no orientation block):
   OK
-- with orientation= and collision_simulation_path= (what rolling.py adds):
   FAILED: TypeError: ScenarioSample.__init__() got an unexpected keyword argument 'orientation'
```

`ScenarioSample` 是 `@dataclass(frozen=True)`，没有 `__init__` 覆写、没有 `**kwargs`，
且全仓库只有一个定义（已 grep 确认）。因此**当前本地副本上任何 rolling 采样都会抛 `TypeError`**，
与是否声明 `orientation` 块无关（调用点无分支保护）。

> 这与 `log/V3.6` 记录"T1（#1/#2/#3/#4）11 条完成"并不矛盾：
> 那 11 条是在**服务器**上跑的，服务器副本与本地这份中间态副本并不一致

### 6.3 `physics_fps: 560` 被 240 Hz 硬门控拒绝，且不存在 `setTimeStep` 调用

`rolling_gso.yaml` 设 `physics_fps: 560`，其注释还声称
"before that was fixed a finer step_rate silently stretched simulated time instead of
shortening the step"，暗示已经修好。但事实是：

- `physics/pybullet_backend.py:36-37` 仍然是上游原样：

  ```python
  if sample.physics_fps != 240:
      raise ValueError("PhyCo-Sim's current backend assumes a 240 Hz Bullet timestep")
  ```

  与上游该文件第 20-21 行**逐字符相同**（已 diff 确认）。

- 全工作副本（含 `third_party/`）搜 `setTimeStep`，**只有 2 处命中，都在
  `rolling_gso.yaml` 的第 38、39 行，且都在注释里**。**没有任何一处是实际函数调用。**

实测证明（`verify_240.py`，门控在 `import kubric` 之前所以无需 pybullet）：

```text
Calling PyBulletBackend.simulate() with sample.physics_fps = 560
  -> ValueError: PhyCo-Sim's current backend assumes a 240 Hz Bullet timestep

For contrast, physics_fps = 240:
  -> FileNotFoundError: PhyCo-Sim Kubric package not found: ...\third_party\phyco-sim\kubric\kubric\__init__.py
```

对照组说明：240 能**越过**门控（随后因本地 submodule 未初始化而报另一个错），
560 则**恰好被门控拦下** —— 证明拒绝 560 的就是这条门控本身。

**结论**：`rolling_gso.yaml` 的 `physics_fps: 560` 在当前代码下不可能跑通；
"physics adapter 中有显式 `setTimeStep` 调用"这一声明**不成立**。
（`rolling_gso.yaml` 本身也从未出现在 §4.3 的部署清单 `t3dev_deploy.sh` 中 ——
该脚本明确声明"never touches `configs/scenarios/rolling_gso.yaml`"。）

### 6.4 `projectile` 只是 `tools/` 里的授权配置，未进入工作副本

- 因此"新增 projectile scenario"在本副本中**没有体现**。
