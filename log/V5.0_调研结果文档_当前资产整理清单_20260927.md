## 0. 结论

1. 当前真正可在本项目管线中直接运行的资产为：**6 个 GSO 来源物体**（5 个 `gso_*` 资产 + 已规范化为 `special_plush_elephant` 的 GSO 小象）、1 个转盘和 1 个 ReplicaCAD 公寓场景。这些资产的 visual/collision 均已从服务器最终副本备份回本地。
2. HF 私有仓库当前登记 14 项资产：学长原有 11 项 + 我们的 `special_plush_elephant`、`replicad_apartment`、`turntable`。上述 6 个 GSO 来源物体中，除小象外的 **5 个 `gso_*` 资产尚未进入 HF**。
3. 学长 11 项资产的 manifest/collision 描述在本地，但本机和服务器缺少其中多数 visual/source 大文件；在重新从 HF 下载前，不能把它们视为本地可运行资产。
4. 当前环境物理只加载被选中的支撑面碰撞；墙、桌椅、柜体等未登记碰撞的场景内容仍是**纯视觉几何**。因此 `replicad_apartment` 目前不是“全场景可交互”。
5. 新增资产的主线只接受**真实视觉 + 刚体语义 + 真实尺度 + 独立碰撞体 + 明确许可**。外观明显柔软、但没有软体求解和逐顶点渲染支持的模型，不进入高动态刚体样本。

### 2.1 当前对象资产需要修正的共同问题

- 5 个未上传 HF 的 GSO 资产在规范目录中缺少 `source/`，但原始文件仍在 `models/gso/`；上传前需把原始文件按规范补回并记录 SHA256。
- GSO manifest 中的质量范围约为 0.14–4.4 克，与花盆、纸盒、收纳盒、蛋白粉罐的现实质量不符。新一轮“真实物体”实验前必须按商品类别/体积重新标定，不能继续把这些值当作真实质量。
- `special_plush_elephant` 和布艺方块虽然被当前后端当作刚体，但视觉材料会使高动态碰撞显得不真实；在软体通路完成前限制使用场景。
- OBJ 输入经过 `generate_collision_mesh.py` 时存在 +90° 坐标系缺陷；小熊已逆变换修复。未来 GSO/OBJ 资产必须在生成后执行 visual/collision AABB 逐轴对齐检查。

### 3.1 ReplicaCAD 当前事实

- 场景 visual 为单 mesh `environment`，保留材质、86/86 贴图、7 盏作者灯和作者 World。
- 求解器使用从原场景提取的 84.68 m² 地板网格；放置区是经射线核验的 18.87 m² 空地。
- `asset.yaml` 中 visual size 仍写成 `[1.0, 5.4, 3.13]`，与实测地板跨度约
  `7.26×12.99 m` 不一致，属于待修 manifest 元数据。
- 当前 PyBullet 后端只加载选中 surface 的 URDF；未登记的墙、家具、楼梯等不能阻挡被仿真物体。
- CC BY-NC 4.0 禁止商业用途；任何商业演示必须替换该环境。
