## 1. 目标与范围

### 1.1 总目标

产出**带逐帧物理标注的视频资产**，用于物理世界模型 / 可控运动生成模型的训练与评测。

### 1.2 本轮范围（第一期）

在**无交互环境**（场景中只有一个运动物体，除静态地板外无其他动力学物体、无碰撞参与）下，生成单个物体的两类运动：

| 编号 | 运动类型 | 物理含义 | 本期状态 |
|---|---|---|---|
| A | **固定圆周运动** | 物体沿固定圆形轨迹匀速运动，含自转 | ✅ 已实现并验证 |
| B | **阻尼运动** | 速度按指数规律衰减的黏性阻尼运动 | ✅ 已实现并验证 |
| C | 旋转运动 | 纯自转 | ⏸ **本期不做**（按要求暂缓） |

### 1.3 明确不在本期范围

- 软体 / 形变物体（soft body、tet 网格、Neo-Hookean）
- 多物体交互、碰撞、堆叠（Jenga、台球等上游场景）
- 外力施加（force / torque / impulse）
- 纹理随机化（Poly Haven PBR 贴图）与 HDRI 背景随机化

## 2. 调研结论

### 2.1 上游管线构成

PhyCo-Sim 本质是 **Kubric（Google Research）的一个改造分支**，仓库内 `kubric/` 是 vendored 的完整框架。其运行链路为：

```
Kubric Scene（物体 + 相机 + 光照）
        ↓
PyBullet 物理积分（DIRECT 无头模式，240 Hz 子步）
        ↓
逐帧位姿写入 Blender 关键帧（keyframe_insert）
        ↓
Blender/Cycles 渲染 → EXR 多层 → 后处理拆成 rgba / depth / segmentation
        ↓
metadata.json + 视频
```

**关键点**：物理与渲染是**解耦**的。PyBullet 只负责算出每帧位姿，真正出图靠 Blender 按关键帧求值。这意味着只要给定一条轨迹（无论来自求解器还是解析式），渲染与标注链路完全一致。

### 2.2 可复用的上游资产

| 类别 | 内容 | 已落地位置 |
|---|---|---|
| 网格模型 | 108 个文件（45 `.obj` / 40 `.urdf` / 17 `.mtl` / 3 `.vtk`），共 10.85 MB | `models/phyco_sim_objs/` |
| 相机/场景/元数据工具 | `kubric_utils.py` 的取景、投影、深度归一化函数 | 参考实现 |
| 场景脚本骨架 | 9 个 `run_*.py` 场景（球落地、摩擦滑动、台球等） | `code/vendor/phyco-sim/src/` |
| 并行调度 | `run_parallel_*.py`（ThreadPoolExecutor + 多 GPU） | 参考实现 |

### 2.3 上游方案在本机的三项硬性不兼容（已定位并解决）

| # | 问题 | 上游做法 | 本机实际 | 解决方案 |
|---|---|---|---|---|
| 1 | **Blender 版本** | 固定 Blender 3.4 + `bpy` wheel | 本机为 Blender 5.2（Python 3.13），`bpy` 无 Windows wheel 且 4.x 起 `bpy.ops.import_scene.obj` 被移除、Principled BSDF 插槽改名 | **独立部署 Blender 3.4.1** 于 `tools/runtime/`，全程用 `blender.exe --background --python` 驱动 |
| 2 | **pybullet 无 Windows wheel** | Linux manylinux wheel | PyPI 上 pybullet 无 Windows 构建 | 采用 **conda-forge 的 `pybullet 3.25` cp310 win_amd64** 扩展模块 |
| 3 | **`verbose=False` 崩溃** | Kubric 默认走 `RedirectStream` | Windows 上 `os.dup2` 重定向 Blender 自有 stdout 导致 `EXCEPTION_ACCESS_VIOLATION` | 强制 `verbose=True` |

> 另有一项隐蔽问题：`pip install OpenEXR` 默认装 3.4.x，与 Blender 3.4 链接的 OpenEXR 运行时不兼容，**必须锁定 `OpenEXR==3.2.3`**，否则读 EXR 时崩溃。

### 2.4 物理引擎的重要限制（直接影响方案选型）

Kubric 加载 URDF 时固定使用 `useMaximalCoordinates=True`。在该模式下，本机 pybullet 构建：

- `changeDynamics(...)` **返回成功但静默失效**（阻尼/摩擦仍为默认 0.01 / 0.5），且调用后**物体被冻结**，不再响应任何速度；
- URDF 中的 `<dynamics damping=... friction=.../>` 同样**被忽略**。

**实测证据**（三组对照，各步进 60 子步，初速 3.0 m/s）：

| 工况 | 处理 | 位移 |
|---|---|---|
| 基线（仅通过 trait 设初速） | 无 `changeDynamics` | **0.750 m** ✅ |
| 设初速后调用 `changeDynamics(linearDamping=1.2)` | 有 | **0.000 m** ❌ |
| URDF 内嵌 `<dynamics damping="1.2">` | 有 | 3.0 m/s 恒定，阻尼仍为 0.01 ❌ |

**结论**：在本机环境下，**无法通过求解器参数控制阻尼**。因此阻尼运动改用**解析解**直接生成轨迹（见 §3.2），这同时带来标注精度更高的好处。

## 3. 技术方案

### 3.1 运动 A：固定圆周运动

**定义**：物体质心沿半径 `R` 的圆做匀速圆周运动，同时绕圆法线自转。

**参数化**（物理量优先，而非"转几圈"）：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--radius` | 1.2 m | 圆半径 |
| `--period` | 2.0 s | **转一圈所需时间**（主控参数） |
| `--plane` | `z` | 圆所在平面的法线（`z` = 水平圆） |
| `--spin_per_orbit` | 1.0 | 每公转一圈自转圈数 |
| `--height` | 0.9 m | 圆心离地高度 |

**导出物理量**（解析式，逐帧精确）：

```
θ(t) = ω t                     ω = 2π / period
p(t) = c + R·(cosθ, sinθ)      位置
v(t) = R·ω·(−sinθ, cosθ)       切向速度，|v| = Rω
a(t) = −R·ω²·(cosθ, sinθ)      向心加速度，|a| = Rω²
```

默认参数下：`ω = π rad/s`，`|v| = 3.77 m/s`，`|a| = 11.84 m/s²`，物理量均处于合理量级。

> **实现说明**：圆周运动本身是**规定轨迹**（prescribed），不是求解器积分结果。这是刻意的：真实求解器无法给出完美闭合的圆，而"固定圆周运动"的定义就是轨迹固定。轨迹虽为规定，但**速度、加速度标注是解析精确的**。

### 3.2 运动 B：阻尼运动

**定义**：物体以初速 `v₀` 出发，仅受线性黏性阻尼作用，速度按指数衰减。

**参数化**：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--speed` | 3.0 m/s | 初速 v₀ |
| `--linear_damping` | 1.2 s⁻¹ | 衰减率 k；**总位移 = v₀/k** |
| `--angular_damping` | 1.5 s⁻¹ | 角速度衰减率 |
| `--spin_rate` | 6.0 rad/s | 初始自转角速度 |
| `--direction` | 0° | 初速方向（XY 平面内） |

**模型与导出物理量**：

```
v(t) = v₀·e^(−kt)                       速度
x(t) = x₀ + (v₀/k)·(1 − e^(−kt))        位置（渐近位移 v₀/k）
a(t) = −k·v(t)                          加速度
ω(t) = ω₀·e^(−k_a t)                    角速度
θ(t) = (ω₀/k_a)·(1 − e^(−k_a t))        姿态角
E_k(t) = ½v(t)²                         动能，按 e^(−2kt) 衰减
```

起始点自动设为 `x₀ = −½·(v₀/k)`，使整段运动在画面中居中。

**自校验**：生成后对 `ln v(t)` 做最小二乘拟合，反推 k 并与标称值比对。实测 `k_fit = 1.2000000000000013`，相对误差 `1.1e-15`（机器精度），`R² = 1.0`。

### 3.3 输出规格

每个视频产出一个目录，包含：

| 文件 | 内容 | 格式 |
|---|---|---|
| `rgba_%05d.jpg` | RGB 帧 | JPEG q95 |
| `segmentation_%05d.png` | 实例分割掩码（无损） | uint16 PNG，0=背景，1=地板，2=物体 |
| `depth_%05d.png` | 深度图 | **uint16 PNG，单位毫米**，0=无效 |
| `metadata.json` | 完整物理标注 | JSON |
| `rgb.mp4` / `segmentation.mp4` / `depth.mp4` | 视频 | H.264 |
| `qa_contact_sheet.jpg` | 人工质检缩略图（非数据集载荷） | JPEG |

### 3.4 标注 Schema（`metadata.json`）

```jsonc
{
  "schema_version": "1.0",
  "video_id": "circular_objectball_radius1.2_period2.0",
  "scene": {
    "resolution": [768, 432], "fps": 24, "step_rate": 240,
    "num_frames": 96, "duration_s": 3.958, "gravity": [0,0,0],
    "samples_per_pixel": 64, "seed": 1234
  },
  "camera": {
    "position": [...], "quaternion": [...],
    "focal_length": 42.0, "sensor_width": 36.0, "field_of_view": 0.81,
    "intrinsics": [[fx,0,cx],[0,fy,cy],[0,0,1]],   // 内参矩阵
    "extrinsics": [[...4x4...]]                     // 外参矩阵
  },
  "camera_framing": { "final_distance": 3.28, "final_center": [0.499, 0.500], ... },
  "motion": {
    "type": "circular",
    "radius": 1.2, "period_s": 2.0, "omega_rad_s": 3.1416,
    "tangential_speed": 3.77, "centripetal_accel": 11.84,
    "revolutions_in_clip": 1.98, "dynamics": "analytic_kinematic"
  },
  "objects": [ { "name": "ball", "scale": 0.3, "mass": 1.0,
                 "segmentation_id": 2, "mesh_obj": "...", "mesh_urdf": "..." } ],
  "frames": {
    "0":  { "ball": { "t": 0.0, "position": [...], "quaternion": [...],
                      "velocity": [...], "acceleration": [...],
                      "angular_velocity": [...], "speed": 3.77,
                      "centripetal_accel": 11.84 } },
    "1":  { ... }
  }
}
```

**要点**：
- `frames` 是**逐帧完整物理标注**——位置、四元数姿态、线速度、**线加速度**、角速度、速率。上游 README 承诺的 schema 与实际代码不符（上游把逐帧数据放在 `animation_data.pkl`，且不含相机内参），本方案统一收敛到单一 JSON。
- 相机内参 `intrinsics` / 外参 `extrinsics` **确实写入**，可用于把像素反投影回三维——这是物理标注可用的前提。

`generate_batch.py` 内置四档 preset：

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| CPU 渲染耗时长 | 全量产出周期长 | ① 按需下调分辨率/采样；② `--workers 2` 并行；③ 先出 `smoke` 再放量 |
| D 盘空间 21.2 GB | 大批量产出可能紧张 | 单条约 12 MB，`full` 仅 0.6 GB；如需扩容可用 H 盘（剩余 158 GB） |
| pybullet 求解器阻尼失效 | 无法用求解器做阻尼 | 已改解析解；若未来需要求解器阻尼，须改 Kubric 的 `useMaximalCoordinates=False` 并重新验证 |
| 无 GPU | 无法用 Cycles GPU / OptiX 降噪 | 已确认 CPU + OpenImageDenoise 可用，仅影响速度不影响质量 |
| `OpenEXR` 版本漂移 | 重新装环境时崩溃 | 已在文档固化 `OpenEXR==3.2.3`；建议后续生成 `requirements.lock.txt` |
| 解析轨迹被质疑"不是真仿真" | 评审风险 | ① 明确标注 `dynamics: analytic_*`；② 圆周/阻尼本身即为规定运动；③ 后续可补求解器积分版本做交叉验证 |
